# openLab — Agent Instructions

openLab is an open-source (GPLv3-or-later) show-playback system for theatre, a QLab 5 alternative. It runs live shows: **a crash or wrong behaviour can stop a performance.** Correctness and robustness beat speed of delivery every time.

## Read before any work
1. [`REQUIREMENTS.md`](REQUIREMENTS.md) — what we build (IDs like `AUD-07`, release tags like `v0.0.1`, scope limits in §21).
2. [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — how we build it. Do not deviate; if it seems wrong, stop and report back instead of improvising.
3. [`PROGRESS.md`](PROGRESS.md) — what is done and what is next.

## Layout
- `engine/` — Rust workspace: `crates/core` (pure logic, no I/O), `crates/audio` (devices, decode, real-time mixer, offline render), `crates/engine` (binary: control thread, WebSocket, OSC, persistence).
- `mac/` — Swift + AppKit app, Xcode project generated by XcodeGen from `mac/project.yml` (never commit `.xcodeproj`).
- `docs/` — architecture, file format, protocol, OSC. Machine setup (XCTest deploy target, Automation Mode, signing, shared sccache): `docs/dev-setup.md`.

## Commands
```
make lint        # cargo fmt --check, cargo clippy -D warnings, swift format lint
make test        # all Rust tests + mac unit/UI tests
make test-rust   # Rust only
make mac         # generate project + build app (includes universal engine)
make verify-bundle  # check the Release app is universal, minos 12.0, validly signed
make prepush     # pre-push gate: lint, Windows clippy, Rust tests, app build, app tests when app code changed; prints PREPUSH PASS or PREPUSH FAIL: <step>
```

## Non-negotiable rules
**Real-time audio thread** (anything called from the audio callback):
- No allocation/deallocation, locks, syscalls, logging, formatting, or disk I/O. Preallocate; return objects to the control thread for freeing.
- Communicate only via `rtrb` SPSC queues and atomics. `assert_no_alloc` must stay enabled in debug/test.

**Engine Rust code:**
- No `unwrap`, `expect`, `panic!`, or unchecked indexing in non-test code. Return `Result`; surface failures as broken-cue state, warnings or log entries.
- `openlab-core` stays pure: no threads, clocks, files, sockets. Time is passed in.
- `unsafe` only outside core, with a `// SAFETY:` comment and a test.
- Validate every external input (show files, media, OSC, protocol messages). Bad input → warning, never crash or hang.
- Debug and release behave the same. `cfg(debug_assertions)` may add checks that log or count, never change behaviour.
- A caught fault is confined to the smallest unit (voice, cue, peer, document), which is dropped or marked broken and reported; the rest of the show keeps running.
- A validation or limit applies on every path that creates or changes that data; test each path.

**Tests:**
- Every change ships with tests. Every bug fix ships with a regression test that failed before the fix.
- No real-time sleeps or wall-clock dependence in tests — use the virtual clock / offline render driver.
- Add tests to the existing file for that behaviour and reuse `tests/common`; no new harness types. No milestone or task IDs in code, comments or test names (requirement IDs are fine).
- Integration-test support modules (`tests/common/mod.rs`) start with `#![allow(clippy::unwrap_used, clippy::expect_used, clippy::panic)]`: clippy's in-test allowances only cover `#[test]` fns and `#[cfg(test)]` items.
- A test that cannot run here says so as a skip or a failure (e.g. `soak_rt` fails instead of skipping with `OPENLAB_SOAK_RT_REQUIRE=1`); a required test never reports a pass by returning early.
- Test-only code (fakes, fault switches, fixtures) never compiles into a Release product.
- Before reporting done: `make prepush` (it runs Windows clippy). Path tests: expect `\` on Windows or use `to_portable`; APFS refuses non-UTF-8 names.

**Contracts:**
- Protocol change → update Rust types in core, regenerate fixtures in `engine/fixtures/protocol/`, update Swift `Codable` types, update `docs/protocol.md`. Same commit.
- Show-file change → bump `format_version`, add a migration step + fixture of the old version, update `docs/file-format.md`. Same commit.
- New dependency → must be GPLv3-compatible, justified, and added to the table in ARCHITECTURE §12. Prefer stdlib or an existing dependency.
- Docs describe what exists; plans go in issues. A claim about CI, lints or tests is checked against `ci.yml` / `Cargo.toml` when written.

**macOS app:**
- Swift 6, AppKit only, deployment target macOS 12.0. No SwiftUI, no Observation framework, no APIs newer than 12 without `#available` fallback. No third-party Swift packages without approval.
- View controllers talk to `WorkspaceStore`, never to the socket.
- Layout and workflow follow QLab 5 closely; all assets are original or SF Symbols. Never copy QLab icons, artwork, names or documentation text.
- All user-facing strings go through `Localizable.strings`.

**Every source file** starts with `SPDX-License-Identifier: GPL-3.0-or-later` (in a comment).

## Behaviour decisions
- Functional behaviour is grounded in QLab 5. When the brief doesn't settle it, follow QLab 5 and say so in your report. If `~/qlab-ref` exists, search it first (`~/qlab-ref/qlab-ref search "<words>"`, then `show <page>`; paraphrase and cite pages, never copy text into the repo), then https://qlab.app/docs/v5/. If still unsettled, implement the likeliest behaviour and add an `assumed` row to [`docs/todo/open-qlab-questions.md`](docs/todo/open-qlab-questions.md) (assumption, what you searched). Never block on the user. Before adding a row, search that file: every answer the user has given is recorded there, and a question is never asked twice.
- Scope matches QLab 5 (user decision 2026-10-29): openLab builds what QLab has and drops what it doesn't, even when a requirement once asked for it. Where QLab's behaviour is known, copy it without asking. Ask only when QLab is unknown or show safety is at stake.
- UI layout follows QLab 5: before building or changing a screen, look it up in `~/qlab-ref/ui` if it exists (`README.md`, then `surfaces.json`, `menus.json`, `cue-types.json` and `shots/`). Cite its surface ids. It is a local reference only: never copy its text, label lists, tooltips or screenshots into the repo, issues or PRs. Describe layouts in your own words, and give openLab's controls our own similar names.

## Tracking
- Open work is GitHub issues (`gh issue view N`). Work only on the issue(s) you were assigned. Tick each issue **Checklist** box as soon as that part is implemented **and tested**; say in your report what is missing for any box left open.
- Do not edit `PROGRESS.md` or tick `REQUIREMENTS.md` in a task branch; the orchestrator does after merge.
- Missing work you discover: report it (the orchestrator files an issue); don't expand scope. Niche QLab parity not needed for v0.0.1 goes to the `v0.0.2` milestone.
- Notes and decisions go in the issue, the PR or the docs, never appended to `PROGRESS.md` lines.

## Findings policy (the only copy: agents and the orchestrate skill link here)
- **High**: a show can stop, sound wrong, fire or stop the wrong cue, lose data, or the process can crash, panic or hang, on any input, however found (fuzzers and property tests included). Any input from outside the process is reachable.
- **Medium**: wrong behaviour; a false or stale claim in a contract doc, ARCHITECTURE.md or this file; a missing test on a changed path; behaviour that differs between debug and release; duplication, dead code or a parallel test harness that the change adds.
- **Low**: everything else.
- High and Medium block merge. Only the user downgrades a Medium; quote it in the PR.
- Lows: fix in the same round when the fix is small and in a file the PR touches; otherwise a `low` issue in the current milestone. A milestone closes only when its `low` issues are fixed or re-milestoned with a reason.
- Pre-existing findings in a touched file: a High (crash, panic, hang included) is fixed in this PR or the PR waits for its fix. A pre-existing Medium becomes a `severity:medium` issue in the current milestone; it blocks the milestone, not this PR, unless the PR makes it worse.
- A generator, fuzzer or oracle finding that is not a crash, panic or hang and needs input the loader already rejects: fix the generator or oracle, not the product.
- One regression test per bug, no variant matrices.

## Git
- Commit with plain terminal commands: `git add …` then `git commit -m "…"`.
- **Never add `Co-authored-by` or any AI-attribution trailer.**
- Message style: short imperative subject with area prefix, e.g. `core: add continue-mode state transitions`, `audio: equal-power fade curve`, `mac: cue list outline view`.
- Don't push, rebase shared history, or force anything unless the orchestrator asks. Changes reach `main` only through a PR that the orchestrator merges after CI is green; nobody pushes to `main` directly.
- Agent commits are authored by the repo-local git identity; see `docs/dev-setup.md`.
