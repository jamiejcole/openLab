# macOS app structure

Must not break: view controllers never touch the socket; Show Mode never opens an alert or sheet except the modal cases listed below; meters publish nothing while no `MeterView` is on screen.

Stack rules (Swift 6, AppKit, macOS 12.0, no SwiftUI/Observation/third-party packages, SF Symbols, `Localizable.strings`) are in CLAUDE.md.

## Chain
- `EngineClient` (socket, reconnect, message codec; `URLSessionWebSocketTask`, `Codable`) -> `WorkspaceStore` (mirrored model and runtime state, publishes changes) -> AppKit view controllers.
- View controllers never touch the socket.
- One window per open workspace, each with its own `EngineClient` bound to that doc (`hello { workspace }`) and its own `WorkspaceStore`.
- An app-level session holds the unbound connection and owns launch, New/Open/recovery flows, the workspace list, recent files and the quit walk (one save prompt per dirty workspace).
- The front window decides which doc GO, Pause All and other window-scoped keys address. Esc sends the app-scope `panic`.
- Edit > Undo and Redo act on the workspace whose window or settings window is key (`AppController.undoController`), so a settings change (the OSC passcode table, NET-02) is undone from the settings window; every other window-scoped key still needs the workspace window itself.
- Closing a workspace while cues play asks first. Closing the last one shows a launcher window.
- No `NSDocument` subclass. UI is built in code: no storyboards or XIBs, main menu included.
- Main window layout follows QLab 5 (UI-07): toolbar and GO area on top, cue list (`NSOutlineView`, view-based, cell reuse for 2,000+ cues) centre, sidebar, tabbed inspector below. Dark appearance by default.

## Meters (AUD-19, NFR-26)
- `WorkspaceStore.meters` (`MeterBank`) max-folds each `meters` push into preallocated per-source slots and publishes nothing.
- A `MeterView` registers only while on screen (in a window, not hidden or occluded). The bank's 60 Hz timer runs only while a view is registered. A push with no view registered is dropped.
- The bank holds views weakly; a view leaves it when its window closes or hides. Levels fall at a fixed dB/s and only changed views redraw.

## Custom views and buttons
- A custom `NSView` whose `draw(_:)` can paint outside its bounds (a line at an x off the visible span) clips first with `NSBezierPath.clip(bounds)`: `clipsToBounds` (available since macOS 10.9) defaults to false on the macOS 14 SDK, and clipping in `draw(_:)` gives the same result on every system whatever the SDK default. `WaveformView`, `MeterBank`'s meter, `LevelMatrixView` and the cue list's progress fill do.
- `Icon` (`Icons.swift`) is the one table of icons. Nearly every concept is openLab's own drawing: a 16-point SVG with a 1-point line in `Assets.xcassets/Icons/<name>.imageset` (`Icon.drawing`, names kebab-case: `kind-audio`, `state-broken`, `time-toggle-up`), loaded as a template image so it takes the tint. They are kept as plain SVG files so another platform can reuse them.
- Panic All draws its own picture (`Icon.fadeOut`); a few concepts are still SF Symbols (`Icon.symbol`: Active Cues' per-cue pause and resume, the engine alarm, a missing file's Target button), all from SF Symbols 1. A missing drawing or symbol is logged once and drawn as the label's text.
- Reset All, Pause All and Resume All share a circle outline; Active Cues' per-cue panic is the falling-curve drawing (the stopping mark's shape). The time headers' chevron points right while the column counts up and left while it counts down (`TimeHeaderCell.icon`).
- A `.texturedRounded` button's shape stays about 24 pt tall whatever its height; a button meant to be big uses `.regularSquare`, which fills it. The sidebar transport buttons are 44 pt with their icons drawn at 20 pt (`transportIconSize`, the vector drawing resized), and a test checks each icon fits the cell's content rect at default and minimum sidebar width.
- Tooltips wait 0.65 s (`ToolTipDelay`, owner decision; macOS's own wait is 1.5 s). `AppDelegate.main` registers it as the `NSInitialToolTipDelay` default before `NSApplication.shared`: AppKit's tooltip manager reads that key once, when the app object is made, as whole milliseconds (650; a fractional value is cut to 0), and a registered default leaves a value the user set winning.
- Every tip, the row status mark's broken reason, Warnings rows and inspector buttons included, is a plain `toolTip` shown by that manager; no view runs its own tooltip timer.
- The sidebar opens inside the least window (800x500): no inspector tab may need more width than the room left (its width less the sidebar's 280 pt), so none grows the window; a test opens it on every tab of every kind and checks the frame (`InspectorWindowFrameTests`). Time & Loops has two rows under the timeline (slices and zoom, then built-in fades) and its root stack fills; Triggers' fade-others control is on two lines and its hotkey field is 130 pt (its prompt truncates).
  - A Fade aimed at a Video cue: its Geometry tab's fields keep their width only below the window's hold on its size (they scroll instead), its thumbnail may shrink to 64 pt (drawn small, never hidden, so the picture's place still shows) and its note wraps at the fields' width.
- Active Cues rows (`ActiveCueCell`): the row stack distributes `.fill`, so the name and times column takes all the room between the buttons; with gravity areas it was as wide as its widest text and a lone time cut the name.
- A looping Video cue held on its last frame after a devamp reports a position a microsecond short of the pass's end: the Duration cell then counts up (`loopPass` returns nil), as Active Cues does.
- The ruler's labels (`WaveformView.rulerMarks`): one under the start handle's triangle starts beside it, one under the end handle's is left out (its tick stays).
- Text that can be long never sizes the window: the masthead's standby name and the sidebar's list names truncate (lowest horizontal compression resistance), so the window keeps its width.
- Cue list columns: only Name changes width with the window; the others keep theirs, so the times stay whole down to the least window width. `fitNameColumn` sets Name to what the others leave (least `nameMinWidth`) on every layout and when another column is resized. It works from the scroll view's frame, always reserving a vertical scroll bar's width (some systems always show one), never from the clip view: the clip view's width changes as scroll bars come and go, and fitting to it can loop.
- Where scroll bars always show, the vertical bar stands over the right edge of the clip view (the clip view is as wide as the scroll view) and AppKit scrolls the columns clear of it: the list the operator sees ends at the bar, which is the room `fitNameColumn` reserves, so a test measures overflow against the bar's left edge, not the clip view's width.
- The sideways scroller is on only while the columns overflow that room. The list's least height and the window's least height each include a legacy scroller's height (`sidewaysScrollerHeight`), so at the least size with the scroller shown the one row is whole above it, and the shrink keeps the selected row in view.
- `fitNameColumn` also turns the sideways scroller on only while the columns are wider than that room (Name at its least): where scroll bars always show, a scroller kept for nothing covered the least list's one row. The vertical scroller is left as AppKit has it.
- No column is narrower than its header's text (`minWidth` from the header cell's `cellSize`; `TimeHeaderCell` adds its chevron), so a header never truncates; Name's least is the larger of that and `nameMinWidth`. Columns are never reordered (QLab only resizes them).
- The header row is `CueHeaderView`: a press on a column title tracks the mouse itself and reports a click on mouse-up over the same column (`onClick`, the time columns' switch), so no header is drawn pressed and none can be dragged. Only a press within AppKit's reach of a user-resizable column's right edge goes to `NSTableHeaderView`, which resizes it. The table delegate's `didClick` stays for accessibility presses.
- The header row is solid: `solidHeader` (on layout) has the clip view that holds the header draw the list's background. AppKit leaves a table header clear over a blur of the rows, and a list squeezed to one row (the least window with the inspector shown) showed the rows behind it through its titles. Overriding `CueHeaderView.draw` for this instead stopped the rows from drawing at all in a forced draw.
- Groups open and close without AppKit's slide (`CueOutlineView` runs `expandItem` and `collapseItem`, the triangle's click included, at zero animation duration): a column change while the slide ran (a resize, the sidebar or Show Mode toggled) never reached the rows outside it, whose cells stayed at the old columns, drawn over the new ones.
- A cue cell's label is a `WholeGlyphLabel`: it truncates at the tail and draws nothing where not even the first letter and the ellipsis fit (AppKit's own truncation draws a letter cut through there, in a deeply nested row at the least list width).
- A list made shorter (window, inspector or divider) scrolls its selected row into view (`keepSelectionInViewWhenShorter`) when the shrink cut off a selected row that was in view, as a selection change does; a list the operator scrolled away from the selection, or one that grows, is left alone.
- The in-place Name editor is at least `nameEditorMinWidth` wide, reaching over the columns to its right and kept inside the list, so a deeply nested row's name can be seen as it is typed; the field is a single scrolling line.
- The first column (`status`) has no title and a fixed width (`CueCell.statusWidth`, not resizable). Its cell lays its images out in fixed slots (`CueCell.statusSlots`): the playhead's room at the row's edge (0), the state (1), the cue-type icon (4; there is no type column), then one slot the preview or override mark (2) and the flag (3) share, the flag giving way (QLab shows a flag in its status area); the mark holding the slot then names the flag in its label and tooltip.
- No first-column mark moves when another appears, so every row's marks line up, indented rows included (indentation is in the Name column).
- A tinted mark is drawn in its colour, and in the selection's text colour (white) while its row is highlighted (`backgroundStyle` emphasized), as QLab draws a selected broken cue's mark.
- Mark colours (`CueStateStyle`, the cell's `fill`): running green; paused, loaded, fading, stopping and every warning (the Warnings list's marker, the footer's warnings count and warning status) `MarkColour.caution`, the system yellow on dark and a deeper golden yellow on light; broken (a red X; the triangle is for warnings only) and output-overridden red; flagged orange; preview blue.
- A cue in its pre-wait or post-wait shows the running mark, labelled with its wait (skill `qlab-behaviour` Q421, Q422). A paused cue's Duration-cell bar is the same caution yellow.
- The footer's all-well status mark is green, its words the plain text colour; an alarm is red.
- A view-based table draws nothing for a row whose `viewFor` returns nil (`objectValueFor` is not used): every table gives each row a cell view. The sidebar's Cue Lists rows are `CueListNameCell`.
- The playhead is drawn by `CueRowView` (a triangle at the row's left edge, over the background and the selection); the status cell's playhead slot keeps the playhead's accessibility label. A closed group around the playhead shows nothing there (Q422). The list's style is `.fullWidth` so rows reach the window's edge.
- A row's tint is `CueKindStyle.shownColour`: the second colour once `store.played` holds the cue (the engine clears it on Reset All, a reset of the cue or its group, and a reopen), else the colour; a colour the app does not know is none. The active-cue stripe uses the same.
- `CueRowView.pattern` (`RowPattern.of`) is drawn over the tint and over the highlight, clipped to the row: `.disarmed` slanted lines, `.skipped` (disarmed with skip-if-disarmed) upright wavy lines.
- The masthead names the playhead cue as the engine reports it, a skipped one too (a GO there moves the playhead on and starts nothing; skill `qlab-behaviour` Q294, Q295).
- Time columns: `timeShown` per column, `.full` counts up while running, `.remaining` counts down; list times use `CueTime.running` (two decimals). `loopPass` gives a no-end cue's place inside its current slice from `progress.position`.
- A drag of cues shows `TargetDropOutline` over the hovered row's Target cell (`targetOutlineFor`): `.sets` in the cell, `.near` elsewhere on the row; removed on drop, drag end and when the drag leaves (`CueOutlineView.onDragExit`).
- `LevelsPanel`: `side` (buttons, the chosen level's mute/gang or "fade this level") beside a scroll view whose `LevelsBoard` holds one vertical `LevelFader` per column over `LevelMatrixView` (value boxes, names, crosspoints). `layoutBoard` works from the scroll view's frame. `levelField` is laid over a box only while typing (`beginTyping`). `fader` is the chosen level's fader.
- Cue outputs above 64: a patch can have 128, but the Levels and Fade tabs show only the first 64 columns (`LevelMatrixView.maxShownOutputs`) and `MeterBank` keeps only 64 channels per source. `LevelSet` holds outputs to 128 and inputs to 64, and writes back untouched what it cannot hold (`unread`), so an edit never drops routing the tab does not show; only "set all silent" and "set defaults" clear it.
- `FadeCurveView` draws the engine's curve shapes (`shape` mirrors `Curve::shape`; keep the two equal). `TargetPathControl` shows a file target; `targetField` is hidden while it does.
- Show Mode locks list editing (`SidebarViewController.listEditLocked`): New List is off and `addList` refuses, the list menu's rename and delete are off and refuse; choosing a list stays on. Lists have no other create, reorder or delete path (no menu-bar item or key); New Cart is always off.
- Sidebar Cue Lists rows are `ListRow`s: a list, or a cue of an open list (`openLists`). An assignment to `lists` in `init` runs no observer, so `init` calls `rebuildListRows` itself.
- Split observers (`startSavingLayout`) run from the window's start, file or not: a divider drag must update the soft size constraint or the divider springs back.
- `application(_:open:)` hands show files to `AppController.openFiles`, which holds them until `launchApplied`. The document type is declared in `mac/project.yml` (`info.properties`); `verify-bundle.sh` checks it.
- A row-menu action must not share a selector name with a menu-bar action: the list's view controller is in the responder chain and would take the menu-bar item.
- `WorkspaceStore` drops `progress` items for cues whose state does not keep progress (`keepsProgress`): the engine sends no last empty `progress`, so an item taken for an ended cue would never clear.
- A `paused` cue with a reason (`device_lost`: its output device was lost while it played or waited; skill `devices`) draws the ordinary paused mark; `displayState` gives it the reason as its detail (the mark's tooltip, `ProblemText.pausedReason`), and the Warnings list words it for a paused cue (`ProblemText.reason(_:state:)`). Its time is the engine's frozen `progress` item. Resume on it is offered as for any paused cue (the engine clears the mark).
- The Warnings list (`WarningRows.make`) holds what is wrong now, once; the footer's count is its row count. The store keeps every warning the engine sends; the rows coalesce: a `cue_broken` refusal joins its cue's broken row as a count line (`warnings.refused.*`) and is dropped from the store once the cue is playable (no problems, no reason); another repeated warning is one row (key: its fields, `late_ms` aside) with its latest words and `warnings.repeated`.
- Device notices carry `device` (docs/protocol.md): one row per device and problem (`d:<family>:<name>`, `device_lost` and `patch_device_missing` one family), titled `warnings.device` with the name middle-cut at `deviceNameLength`, worded from the code (`warnings.device.<code>`), never the engine's `message`. The runtime `device_lost` notice is not listed: the one in the `warnings` list says the same and clears when the device is back.
- No internal id reaches the list: an id the model does not hold is `warnings.unknownItem`, a cue warning about a gone cue is titled `warnings.cueGone`, and ids in the engine text of a notice code that quotes item ids (`idQuotingNotices`: `load_repair`) are named (`ProblemText.namingIDs`); other notices' text (paths, volume names) is shown untouched. `WarningCell` wraps the title as well as the reasons, measured at the row's width.
- In-place list editing covers `preWait` and `postWait` too (`editableColumns`; not an auto-follow cue's post-wait, which shows its duration). A click in the continue column opens `continueMenu(row:)`.
- The cue-editing keys are keys of the workspace key map (`WorkspaceKey.editingActions`, `TransportKeys.editKey(for:)`, `EditKey`): a cell to open (`beginEditFromKey`), the notes (`beginNotesFromKey`: the inspector shown on Basics, caret in the notes), or C and F (`performEditKey`, `CueEditor.setProperty` on the selection). `AppController` tries them after the transport keys and before the cue hotkeys, never while text is typed.
- With several cues selected, E, D and W put the caret in the inspector's one field (`onEditSeveral`, `InspectorViewController.beginField`; nothing when the field is off for them, as an Audio cue's duration), and O in the shared notes; the value goes out through `commitBatch`, one transaction. N, Q and T open nothing.
- A committed cell edit keeps `cellEditor` over the cell (not editable, showing what was typed) until `onEditCell` returns, which is after the engine's answer and so after the model change: closed at commit it would uncover the old value for a moment. `settling` makes sure only the latest commit's answer closes it.
- Workspace settings tabs: General, Keys, Audio, OSC, Network, Video. General's "new cues load ahead" box (`+General`) sends `setNewCuesAutoLoad`; the engine ticks auto-load on cues made afterwards.
- The Video page (`VideoSettingsPane.swift`, commands in `Engine/StageCommands.swift`) is a grid of the workspace's stages: name typed in place, pixel size, display pop-up (this machine's choice: `set_stage_mapping`), keep-black box, layer field (0 to 1000, refused in the page with a line), remove; New Stage below.
- The Video page draws from the model's `stages` and `WorkspaceStore.videoOutputs` (the engine's `video_outputs`, pushed after every snapshot including the bind's and on each change; the page also reads `list_displays` + `list_stage_mappings` on open).
- On the Video page, a stage that cannot be seen (no display, display missing, failed) warns in its row and in the Warnings list (`WarningRows`, id `v:<stage>`: the stage's name, cut at `stageNameLength`, as the title; a short reason, `stageReason`, as the one-line detail).
- A Warnings row for a broken cue, or for an engine warning that names a cue of the workspace, has the cue's number and name as its title and the reasons or the warning on the detail line; other warnings and notices are a title alone.
- The Video page's titles are a grid of their own above the scroll view, so they never scroll away; `fitColumns` gives the display column the spare width first (up to `mostDisplayWidth`), then the name, in both grids, on every resize. Controls are small.
- The Video page always draws what the workspace and engine hold, while a name or layer is typed in too: the field being typed in is drawn again with its text and selection (`typedIn`/`resume`), the old fields' delegates detached so the redraw commits nothing. Add, remove, the box and the pop-up end the typing first, so it commits before them. Every refusal, the page's or the engine's, shows in `messageLabel` and puts the value back; a stage gone says so, never with its id.
- The app's black backstop on output displays of keep-black stages (`BlackBackstop.swift`, owned by `AppController`, fed every live and detached store from `sync`) is in skill `video`. App tests put virtual displays somewhere off every screen through `backstop.readDisplays`.
- App tests start the engine with `TestEngine.start(displays:)` (`--virtual-displays`, offscreen); scenarios take `displays` and `settings`.
- Each `TestEngine.start` is a new engine no other test used: the next one of the same `displays` (no `settings`) starts beside the running test and is handed to the next `start`; spares end with the class. A teardown that does not look at its engine again ends it with `stopInBackground` (the exit wait and folder removal off the main thread; the bundle waits for them at its end).
- Audio (`+Audio`) is the patch table: a row per patch (name typed in place, device pop-up, Edit, remove) with the reason it cannot play under it (`problem(of:)`, from `list_patch_mappings` `resolution`), New Patch above, the volume limits beside. It reads devices and resolutions again (`rereadSoon`) when the engine's warnings or device states change.
- Patch table layout: problem lines wrap at the width the table gets once laid out (`fitProblemLines`, on the holder's width change); a refusal (a patch still in use) wraps to two lines in the message row, its names cut in the middle (`middleCut`).
- `PatchEditorWindowController`, one per patch (`openPatchEditor`; also from the I/O and Levels tabs via `editPatch`, off in Show Mode): name, cue-output count and device on top; tabs Cue Outputs (names), Routing, Device Outputs. Opens with no field focused.
  - Routing grid panes: the header row and left columns are floating `PatchRoutingPane`s; their corner (the column titles) is a third pane over the scroll view, kept topmost (`placeCorner`) so the header scrolls under it. Each row has its cue output's mute button (red M while muted, its level red; Q516).
  - Routing: main fader and a row per cue output with its level box and a `MeterView` bar (`fixedRows`, first 64), a box per device output lit with its crosspoint level from `PatchRouting` (the show's crosspoints over this machine's mapping); a double-click or Return types in the box (`crosspointField`, skill `qlab-behaviour` Q513), a muted device output's header is red; columns the device lacks are red (Q510).
  - Device Outputs: a row each with fader, level box, mute and what reaches it (Q511).
  - The editor reads the devices again on every status change of an output (name, state, outputs) and while a device plays that its list lacks, so a device lost and back shows as it is; a device not connected is said so in the notes, not counted as having no outputs.
  - Foot: Copy Routing pull-down (defaults or another patch) and Unmute All, each one `Transaction` (skill `qlab-behaviour` Q512).
  - Each row's meter is its cue output itself (`OutputMeter.cue_outputs`: the patch bus after the cue output's level and mute, before crosspoints), wherever it is routed (skill `qlab-behaviour` Q514).
- The routing grid's header row and left columns are `PatchRoutingPane`s floating over its scroll view: they stay in view as the boxes scroll.
- A count change is one `channel_count` edit (`setOutputCount`): the engine fits this machine's mapping in the same step and on undo/redo. Picking the patch's own device again resends the mapping only when its length differs from the count; a device offers only as many outputs as the clock device has (`usableChannels`), and the editor says so. The Levels tab shows the patch's count and names (`shownOutputs`, `outputNames`).
- Application preferences: General and Audio (`AudioPreferencesModel` on the session's app connection): the clock device for the next start, and a buffer-size pop-up per listed device (`set_buffer_size`, at once), in a list filling the tab. A row shows no sample rate: `list_devices` carries none.
- Basics colours: two image-only pop-ups of `colourItems` (none, eight basic, twelve extended, separators between; each item's `representedObject` is the colour, its image `CueKindStyle.swatch`). The second sits behind `secondColourCheck`, a lock drawing (`Icon.colourLocked`, open when on): on it unlocks the menu (`secondColourUnlocked` until a pick), unticked it sets `second_color` none.
- A column of a tab ends with `columnFiller()`, which takes the height the tab stretches it to; without it the last control slid to the bottom.
- Triggers: `hotkeyEnableCheck` is the hotkey trigger's switch, mixed for several cues that differ. It shows the stored `hotkey_enabled` with or without a key, so it can be ticked before the key is typed; a recorded key keeps the switch it shows. Off keeps the key, drawn faint. On is checked with `HotkeyRules` for each cue's key (and the cues' keys against each other) and refused for all on a clash. `cueHotkeys` lists only keys that are on; `storedCueHotkeys` every key, for the key map.
- The Triggers tab's right side (`InspectorOthers.swift`): fade out and stop others (box, scope, time) and duck or boost others (box, dB, time), each edit changing only its part of each cue's own setting. The times and the dB are `InspectorField`s; the dB is `OthersLevel` (a plain number boosts). The box reads boost above 0 dB, relabelled as the number is typed. Off, the values are kept and drawn off.
- `triggers`, `fade_and_stop_others` and `duck_others` are replaced whole: an edit sent before the last one is answered builds on `pendingWholes` (a transaction's included), never on the stale model.
- Keys (`+Keys`) is the key map: workspace and cue-editing actions in two columns, each a `HotkeyRecorder`, a clear button and a reason line beside it (`KeyRefusal`, one at a time). It refuses what the engine would (another action's key, a cue's hotkey, Esc, Up/Down) and takes a menu command's key, which then warns (Q80).
- The Network tab (`+Network` files) is a grid of destinations drawn from the model like the OSC table; files added to `mac/openLab` need `make project` before a build sees them.
- `WorkspaceWindowController` removes its split observers in `windowWillClose` (`stopSavingLayout`), and their blocks hold the split weakly: a block-based observer left in the notification centre keeps what it captured for the life of the app, and every closed window's view tree stayed alive.
- `stopSavingLayout` also cancels the delayed performs aimed at each split: a split queues a save of its own arrangement after a layout, and that timer holds the split (and the views) until it fires. `testAClosedWindowsViewsAreReleased` checks the views are gone at once, with no run-loop turn.
- A closed workspace gives up its window, its controller and the windows it owns (settings, patch editors, Find Missing Files, pre-show check, log), cues playing or requests unanswered (`testAClosedWorkspaceReleasesItsWindowAndTheWindowsItOwns`). `windowWillClose` closes the status popover and ends a sheet still up (as its Cancel): either would hold the window.
- Nothing that waits (a Task, a timer) holds a window controller or the `AppController` strongly: `bounded`'s timeout holds only its gate and is cancelled when the work answers.
- Test bundle: `EngineTestObserver` is its principal class (`OpenLabTestObserver`). After each test it closes any window the test left open and forgets the app's last event (`currentEvent` holds its window).
- A window the test opened that is still alive two tests later fails the next test to start, naming the test that left it (a kept window keeps its window-server surface; hundreds stalled the CI runner's window server). Windows of other system frameworks (`isAppWindow`) are not counted.
- A test that checks releases runs its steps in an autorelease pool of its own (`drained` in `AppControllerTests`): an async test's pool holds what it touched until it ends.
- XCTest keeps every test case object to the end of the run, so a tearDown closes and sets to nil the windows, view controllers and rigs in its properties. Window animations are off in the test host: an animation holds its window until it ends.
- The row menu's Edit submenu (`editSubmenu`, `RowEdit`) sets one property on `rowMenuCues` through `CueEditor.setProperty(_:of:)`, one transaction. The I/O tab is `InspectorIO.swift`, a grid; the patch goes out as `kindFields(["patch": id])`.
- Video cues: the Video button (its own toolbar group after Audio) and Cues > Video (Cmd-3) add one on the workspace's first stage (`kindJSON(stage:)`). `Cue.takesFile` marks Audio and Video cues (a file target). A drop or Choose makes or retargets by the file's kind (`CueEditor.cueKind(forFile:)`: `audioExtensions`, `videoExtensions`); a file of the other kind is refused with a reason. `WorkspaceWindowController.pickFile(kind)` is the chooser.
- A Video cue's Duration: a movie's from its probe, a still's typed (`InspectorEdit.editsDuration`, `videoDuration`; empty or 0 clears it, sent as `kindFields(["duration": null])`).
- A Video cue's I/O tab (`VideoIOControls`, rows hidden for an Audio cue): the file and Choose, the format the probe read (`CueMediaDuration.picture`), the stage pop-up (stages, a separator, None) and the stage's pixel size. Several Video cues: I/O shows the stage they share or mixed.
- A Video cue's sound: `Cue.sounds(_:)` (an Audio cue, or a Video cue whose `media_durations` item has `audio_tracks`) is the one question every sound surface asks; a still, a silent movie and a file not probed yet have none. `LevelSet(kind:)` reads a Video kind's `levels` as an Audio kind's.
  - Tabs: `InspectorTabs.ids(for:model:media:)` adds `levels` after Time & Loops for a Video cue with sound and drops a Fade's `fadeLevels` while its Video target has none; a runtime change for the cue (or a Fade's target) renders again, so the tabs follow a replaced file without reselecting. The Levels tab is the Audio cue's `audioLevels` panel (meter source `.cue`), nothing of its own.
  - I/O rows shown only with sound (`soundRow`, `patchRow`): the sound format under the video format (`soundText`: codec name from `inspector.io.audioCodec.<code>`, else the code; channels; kHz) and the output patch with Edit. The patch pop-up is the Audio cue's, with a separator and None after the patches for a Video cue (`outputPatchHasNone`, `outputPatchChoices`); None is `kindFields(["patch": null])` and the cue shows `no_patch`.
  - A file with several audio tracks shows `trackPopup` in place of the text (numbered items, `audio_track` by `kindFields`); a stored track the file lacks is the pop-up's last item, named as missing and chosen (`inspector.io.trackMissing`), with `trackNote` beside it saying the first track plays, for a one-track file too; picking a track of the file clears the engine's `audio_track_missing` warning, picking the missing item does nothing.
  - New Video cues (toolbar, menu, file drop) take the first patch and `NewCueKind.defaultLevels(patch:)`, the same levels a new Audio cue gets; a patch picked for a Video cue that had none and no levels sends the default levels with it. A paste keeps the cue's own.
  - Several Video cues have the sound row (the shared format or mixed, as text), the patch and the Levels tab only when all of them have sound (`batchTabs(forKinds:allSound:)`, `renderBatchSound`).
  - Edit Patch (I/O and Levels tabs, Audio and Video cues alike) is on only while the shown cues play through one patch the workspace has (`sharedPatch(of:model:)`, `LevelsPanel.hasPatch`): off for a patch of none or gone, and for several cues on different patches, whose Levels columns then show numbers, not one patch's names.
  - Paste Properties: Levels and the output patch go between Audio cues and Video cues with sound, either way (`PasteProperty.soundKinds`, `applies(from:to:media:)`); a patch of none only to a Video cue. A Fade takes a Video cue as its target (`targetRejection`); Set Levels from Target reads `levels(of:durations:)`.
  - Meters only run while a `MeterView` is on screen: an app test that reads a cue's meter shows a Levels tab first.
- A Video cue's Time & Loops tab (after Geometry, `InspectorTabs`) is the Audio cue's `TimeLoopsPanel` (`renderTimeLoops`, `timeLoopsKinds`) shown with `media` `.movie(track:)`: with sound, the waveform of the audio track the cue plays (the track is part of the peaks key, so another track is read afresh); with none (`silent`) no peaks are asked for, the waveform view draws its ruler, trims, slices, fades and lines over the empty background with no message, and presses work at once.
- A Fade cue's Geometry tab (`fadeGeometry`, `InspectorFadeGeometry.swift`, VID-05): shown for a Fade aimed at a Video cue or at nothing yet (`InspectorTabs`), after Levels; not for an Audio or Group target.
  - `FadeGeometryPanel`: a left column with its own stop flag, mode pop-up and Preview at the foot (they send what the Curve and Levels tabs' do), a tick box per value (opacity, position, scale with its lock, rotation) with its fields and a reset.
  - An unticked value's numbers dimmed but kept and editable, opacity rounded to whole percents, a note (`fillsStageNote`) while the target fills its stage, and a thumbnail (`GeometryThumbnail`, never dragged) of the target's stage with its picture where the Fade leaves it (`FadeGeometryValues.applied`, the engine's absolute and relative rules).
  - Each edit sends only the parts of `geometry` it changed; `pendingKind` merges them as the engine does (`merged`, nested parts too). Ranges are the Video cue's (`GeometryControls` ranges). Scenarios `video-fade-geometry*`.
- The Video Time & Loops tab's keep-last-frame box (`holdCheck`, `hold_at_end`) is shown for Video cues only, in the left column under the play count: the row under the timeline is the Audio cue's, so the tab needs no more width (in that row it made the least window grow). A still (`.still`) says it has no timeline and every control is off.
- The Time & Loops playhead line is the engine's `progress.position` (inside a loop, the pass); a loaded cue's is `store.loadedAt` (a progress item of a cue in state loaded). One position at a time (`TimeLoopsPanel.showProgress`): the click's insertion line stays while the engine reports the cue at it (loaded or paused there; no play line drawn) and goes once it reports the cue anywhere else. The timeline click seeks Audio and Video cues.
- A Video cue's Geometry tab (`InspectorGeometry.swift`, `GeometryControls`): placement and style pop-ups, layer (reads top and bottom), opacity in percent, smooth box; in custom mode position, scale with its lock (`scale_locked`: typing x or y sets both), rotation, crop, anchor, each with a reset; `GeometryThumbnail` draws the stage's outline and the picture's shape by `VideoGeometry.corners` (the engine's `quad`, kept equal) on a black of the stage's shape (`backdropRect`), clipped to it.
- Geometry edits go out as `kindFields` through `sendGeometry` (one undo step each); a thumbnail drag sends every move with one coalesce key and the position fields follow at once. A typed value is checked against `GeometryControls.FieldRange` first (the engine's ranges, held equal by a real-engine test): out of range says the field's range in the message line and the field shows the model's value again; an engine refusal says so in words. Not in several-cue editing.
- App tests make movies and stills with `makeTestMedia` / `writeTestMedia` (the bundled stage host's `--make-test-media`, each kind once per test process and copied from there, dated now: `TestMediaCache`; the test card per frame, read back with `stage_probe`); a scenario's `media` makes them by extension. The `Video` test show has two stages and six Video cues (movie, still, still with a duration, no file, long name, a still on no stage); its media is made at test time.
- The `VideoSound` test show (scenarios `video-sound*`): two patches; Video cues with sound, with two audio tracks, silent, a still, with sound and no patch; a Fade on the one with sound and on the silent one; an Audio cue.
- Several cues selected (`InspectorBatch.swift`): `render` draws them with `renderBatch`, the tabs `batchTabs(forKinds:)` gives (Basics and Triggers for mixed kinds). A value that differs shows as mixed (`showChoice`'s hidden Mixed item, `showTicks`, `LevelsPanel.mixed`; notes: an empty `NotesTextView` drawing its `placeholder`, never part of the text).
- Edits of several cues go to `editCues` through `sendEach` / `sendKindEach` / `commitBatch` as one transaction; a typed field is sent only if typed.
- A levels edit on several cues is replayed on each cue's own levels (`LevelsPanel.lastEdit`, `LevelSet.taking`: the one level moved with that cue's own gang, a mute, a gang, set silent or defaults), never copied whole; gangs that differ are not drawn or set (`gangsMixed`).
- With several cues shown (`editsSeveral`) an action is reported even when the first cue already has its result. A mixed level's fader draws no knob (`LevelFader.isMixed`). Notes refused for several cues are offered back as one cue's are. `endBatchControls` restores one cue's controls.
- Paste Properties (Edit menu, row menu, Shift-Command-V): `PasteProperty` holds the categories (Basics also the second colour, load ahead, skip; Triggers the others' fade and duck), which kinds take each and the commands; `PastePropertiesSheet` is the sheet, its ticks remembered in `pasteDefaults` at Apply. `promptPasteProperties` opens it for the selection of that moment; `CueEditor.pasteProperties` sends one transaction. Off in Show Mode, which cancels a sheet that is up.
- Paste Properties' I/O category is the output patch (cues with sound) or a Video cue's stage, offered only when the targets' workspace has that patch or stage (`model`; a stage of none always). Its duration goes only between cues whose duration is typed (`applies(from:to:media:)`): a still's, never a movie's; a still's none goes over as none, never 0.
- The sheet's window (`PasteSheetWindow`) takes Up, Down, Space, Return, Enter and Esc itself, before any control and whatever the keyboard setting: a highlighted row (`PasteSheetRow`), Space ticks it (a category row: the category). A sheet as key window blocks cue hotkeys (`cueHotkeysBlocked`); Esc still panics first. The title is one line, the cue's label cut in the middle.
- Tools > Find Missing Files (`MissingFilesWindowController`, one per workspace: `wc.missingFiles`; `AppController.findMissingFiles`, also the Warnings tab's relink button): on while `canFindMissingFiles` (Edit Mode and a cue with a `media_missing` problem, whatever its kind).
- Find Missing Files asks for a folder (`AppController.pickFolderURL`), sends `relink` with `preview`, and lists the found cues (tick box, cue, file shown from the searched folder down, the full path as its tooltip). Relink sends the ticked rows as one transaction of `.media` edits with full paths (the engine stores them as `relink` would), skipping a cue whose reference changed since the search.
- Find Missing Files, several files of one name: `MissingFileChoiceSheet`, cue by cue (`presentSheet` seam). Show Mode closes the window and any sheet.
- A trim handle drawn at an edge of the waveform is moved inside it so it is whole (`drawHandle`). The playhead, slice and insertion lines are not: at the very edge the clip cuts half their width.
- Waveform press (`WaveformView`): a handle, marker or fade handle drags as before; a press on a slice's drawn count (`onCount`) does nothing until a double-click; anything else is a press (`pressAt`), decided on release.
- Slice play counts are `SlicePlay` (`TimeLoopsPanel.swift`): `.times(n)`, `.endless`, `.skip`, read and written as the show file stores them (a number, the number 0 for endless, the text "skip"; `init(json:)`, `json`).
- The count field over a slice (`sliceCountField`, `SlicePlay(typed:)`) takes a whole number up to `SlicePlay.most`, 0 for skip, a letter or the endless mark for endless, and refuses the rest with `timeLoops.invalid.sliceCount`; `label` is what is drawn and offered back (the number, 0, the mark).
- `WaveformView.skippedRects()` are the spans drawn with `skippedTint` (darker than a playing slice, lighter than what the trims leave out), under the handles, lines and counts; a cue without markers is one slice.
- The left column's play-count field (a cue without slices) still takes 1 and up only, and shows a stored skip as 0. Every slice skipped: the engine's `nothing_plays` problem (`problem.nothing_plays`), the row broken and no duration, like any broken cue. Scenarios `slice-skip` and `slice-skip-light-least` show these states.
- Shorter than `minLength`: a click (`click(atX:)`: section cleared, `insertion` set, `onSeek`). Longer: `selection`, shaded, no seek; past an edge `dragSection` pans by `onPan` (at most `edgeStep` of the width per move). `endDrag` ends a press whose release is lost with no click. No press (click or section) while `isLocked` or `isReading`; a handle drags once the length is known, as before the waves are drawn (worked out: length known, no peaks yet, no failed read).
- The ruler is drawn only once the file's length is known (`showsRuler`): a still, or a file missing or not read, has none.
- Waveform drawing order over the waves: trimmed-off dimming, the section (`sectionWash`, faint `sectionEdge`), the position line (`positionLine`, brighter than the edges), trim handles, slice markers, fades, the play line; a marker at the line hides it.
- While no peaks are drawn the waveform's message says no file, missing (`show`'s `missing`, from a `media_missing`/`media_unsupported` problem), failed, or reading, in `messageColour` on the fixed `waveBackground`. Showing another cue ends a press held on the old one (`endPress`).
- `onSeek` -> `TimeLoopsPanel.onSeek` (only with the file's length known) -> `InspectorViewController.seek`: `transport` `seek` for an Audio or Video cue that does not show broken; a refusal goes to the show log. The play line stays `progress.position`; the insertion line stays where clicked until the cue is reported elsewhere (the engine keeps the cue inside the trims).
- Waveform keys (`WaveformView.editKey`, `keyDown`): Shift-I, Shift-O and M while it is first responder; `AppController.handleKeyDown` passes them on before the cue hotkeys. They use the section's edges, else the insertion line (`setStartHere`, `setEndHere`, `addSlice`); M with a section is one `addSlices` edit. The section and line go when another cue or file is shown (`show(cue:kind:duration:)`).

## Seeing the app
- `make ui-shots SCENARIO=mac/scenarios/<name>.json [OUT=<dir>]` drives the real workspace window on the real engine (stepped virtual clock) and writes `<OUT>/<nn>-<name>.png` per shot plus `steps.log` (each step and what it hit). OUT defaults to `build/ui-shots/<name>`. It builds for testing only when `mac/` app, test, test-show or project files or the engine changed since the last build; editing a scenario needs no build.
- The runner is `ScenarioRunner` in `mac/openLabTests` (test-only, never in a Release product). The window is never ordered on screen or made key: it takes no focus and never moves the pointer, so it runs while the user works. It takes the same machine-wide lock as `make prepush`'s UI tests (`lockf /tmp/openlab-xcuitest.lock`), so it waits for another mac test run. Never run it under another `lockf` on that file: the nested lock waits forever.
- Presses go to the view under the point with the window's press hook; a standard control in a window that is not key ignores `mouseDown`, so its cell tracks the press instead. A pop-up button is refused (its menu needs real input).
- Keys go through the app's own key handling (`AppController.handleKeyDown`, Esc's panic sent to the engine), then a key equivalent, then the window. Cue hotkeys and menu-bar commands are not reached. GO moves the selection to the next cue, so select the playing cue again to inspect it.
- Shots render the window's frame view offscreen at 2x with `displayIgnoringOpacity` (the shared `renderView`): every view draws with the clip AppKit gives it on screen, so a view that does not clip to its bounds shows its overdraw. Forced to draw, a tab view paints a blank white bar over its tabs; `renderView` paints the tab buttons again over it. `cacheDisplay` skips layer-backed subviews; do not use it for pictures.
- Scenario: `show` (a `mac/TestShows` name, `new` for a new untitled workspace, or a `.openlab` path relative to the scenario, opened in place and never saved), optional `media` (`{"media/a.wav": seconds}`: written into a test show's copy first by extension, a test tone, a movie `.mov`/`.mp4` or a still `.png`/`.jpg`/`.tiff`), `window` (`{"width", "height"}`, points, default 1200x800), `appearance` (`dark` default, or `light`), `about` (free text), `steps`.
- A movie in `media` gets audio tracks with `{"seconds": n, "sound": "pcm:2:48000+pcm:6:44100"}` (one per `+` part) in place of the number.
- Steps, one action key each: `select` (cue number, else name, or a list of them selected together); `click` / `double_click` / `drag` (an accessibility identifier; `at`, `from`, `to` as `[x, y]` fractions of the control from its top-left; `modifiers`); `type` (identifier, `text` replacing what the field holds, `""` empties it; `enter` default true).
- More steps: `key` (one character or space, escape, return, tab, delete, left, right, up, down; `modifiers`: shift, control, option, command); `scroll` (identifier; `dx`, `dy`, `precise` default true, `modifiers`, `at`); `magnify` (identifier, `by`, `at`);
  `advance` (seconds of device time, run in tenths); `device` (`lose`: the virtual output unplugged; `restore`: listed again, reopened at the engine's next list read, so `advance` about 2 s after it); `resize` (`[width, height]`); `tab` (inspector tab identifier, or the settings tab while the settings window is focused); `shot` (name).
- `inside` (an identifier, `of`: another): the run stops unless the first lies inside the second (a tab view: its content, below the tabs), as laid out at that step.
- `focus` (`settings`: the workspace settings window, opened without taking focus, is the window the next steps and shots act on; `patch-editor`: the editor a click on `settings-patch-edit-N` opened, drawn off screen (`presentsEditors` false); `workspace` goes back).
- `paste_properties` (a cue number: that cue copied to a private pasteboard and Paste Properties opened for the selection; `tick`: property names). The sheet is never put on screen (`presentSheet`); shots draw it over the window, centred under the title bar. A second step cancels a sheet still up. `focus` `sheet` sends the next `click` (its `paste-property-*`, `paste-category-*`, `paste-properties-apply`/`-cancel`) and `key` steps to the sheet; once it closes the steps go back to the workspace.
- `set_media` (a cue, `file`: its file reference set as an edit; a file that is not there leaves the cue missing it).
- `choose` (a pop-up button's identifier, `item`: that item picked as from its menu, which is never opened). `find_missing_files` (paths of test tones written into a folder, named by `folder`, default `found`): Find Missing Files searches it, off screen; the next steps and shots act on the tool's window (`missing-files-*` identifiers; its list scrolls through `missing-files-scroll`), `focus` `sheet` on its question (`missing-file-choice-*`), drawn over it.
- A step that cannot be done stops the run with a reason and a non-zero exit: an unknown or repeated identifier (the identifiers shown are listed), a disabled control, a press that lands on another view, a cue or tab not found. Reusable scenarios live in `mac/scenarios/`.

## Build
- `.xcodeproj` is generated by XcodeGen from `mac/project.yml`, never committed.
- The engine is built universal (arm64 + x86_64 via `lipo`) by a build-phase script calling `cargo`.
- The stage host (video output windows, skill `video`) is built the same way by `mac/scripts/build-stage-host.sh` into the helper app `Contents/Helpers/openLab Stage.app` (bundle id `dev.openlab.openLab.stage`, `LSUIElement`, minimum 12.0), signed inside-out before Xcode signs the app; Debug builds it with `test-support`. The engine finds it there.
- Release: `make mac`, then `make verify-bundle` (universal, macOS 12.0 on every slice, no test-only code, the app's version equal to the bundled engine's `--version`, the `AppIcon` present, a valid signature; the stage host helper universal, 12.0, signed and `LSUIElement`; the engine linking no AppKit, Metal or QuartzCore; release engine and stage host refusing `--virtual-displays`).
- `make dmg` writes `build/openLab-<version>.dmg`. The app inside is named `openLab <version>.app` so versions install side by side (DST-03). The version is `MARKETING_VERSION` in `mac/project.yml` and `version` in `engine/Cargo.toml`, changed together; `CHANGELOG.md` gets an entry.
- The app icon is `mac/openLab/Assets.xcassets/AppIcon.appiconset`, scaled from `mac/Branding/openlab-logo-1024.png`.
- The app is not sandboxed (it spawns the engine and opens arbitrary media paths). Hardened runtime and notarisation need an Apple Developer account; ad-hoc signed until then.
