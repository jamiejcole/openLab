# macOS app structure

Must not break: view controllers never touch the socket; Show Mode never opens an alert or sheet except the modal cases listed below; meters publish nothing while no `MeterView` is on screen.

Stack rules (Swift 6, AppKit, macOS 12.0, no SwiftUI/Observation/third-party packages, SF Symbols, `Localizable.strings`) are in CLAUDE.md.

## Chain
- `EngineClient` (socket, reconnect, message codec; `URLSessionWebSocketTask`, `Codable`) -> `WorkspaceStore` (mirrored model and runtime state, publishes changes) -> AppKit view controllers.
- View controllers never touch the socket.
- One window per open workspace, each with its own `EngineClient` bound to that doc (`hello { workspace }`) and its own `WorkspaceStore`.
- An app-level session holds the unbound connection and owns launch, New/Open/recovery flows, the workspace list, recent files and the quit walk (one save prompt per dirty workspace).
- The front window decides which doc GO, Pause All and other window-scoped keys address. Esc sends the app-scope `panic`.
- Edit > Undo and Redo act on the workspace whose window or settings window is key (`AppController.undoController`), so a settings change (the OSC passcode table, NET-02) is undone from the settings window; every other window-scoped key still needs the workspace window itself.
- Closing a workspace while cues play asks first. Closing the last one shows a launcher window.
- No `NSDocument` subclass. UI is built in code: no storyboards or XIBs, main menu included.
- Main window (UI-07): `topColumn` (GO area, cue toolbar, Find and Load bars, cue list) and the sidebar sit in `horizontalSplit`, which with the inspector forms `verticalSplit`: the sidebar starts at the window's top and ends above the inspector, which spans the width. A drag of the inspector's divider ending with less than half `minInspectorHeight` left closes the inspector (`dragClosesInspector`, as QLab 5); a divider placed by code never does. Dark appearance by default.
- The footer has one GO-area toggle (hides masthead and cue toolbar, `setVisible(.masthead)`; View > Cue Toolbar stays its own), the warnings button beside the inspector, sidebar and settings buttons, the cue count centred, and no clock.
- The footer has no engine status mark or details (no CPU, dropout, load or disk readouts) and no network-output badge: the red mark on each affected Network cue says it.
- Dropouts and a disk falling behind reach the operator as engine warnings: an `audio_dropouts` device row (its count filled into the text) and a `disk_behind` row in Status > Warnings and the footer's count; a cue's `underrun` notices are one row per cue whose repeat count adds up each notice's `count`.
- `FooterBar.alarmButton` shows `alarmText(status)` (red words and symbol) only while the primary or a secondary output device is lost or failed, hidden when all is well or the engine is away; pressing it opens Status > Warnings.
- A restored layout applies the GO area before the toolbar, so the toolbar's own saved choice wins.
- Edit and Show Mode draw the masthead alike (grey-violet GO with a green edge, boxed standby line and notes, `MastheadView.goFill`/`boxFill`); Show Mode only enlarges (`MastheadMetrics`). The window title is "workspace — shown list".
- A plain press in a row's status column (`CueOutlineView.onStatusPress`) moves the playhead and leaves the selection; `unlinkedHead` stops the follow until the user selects or the playhead moves on.
- An open group is boxed by mode (`GroupOutline`) around its Name cell and its children's, a nested group's box inside its parent's, a Playlist's next child (`WorkspaceStore.playlistNext`) marked on the box's left edge. Each row draws the parts crossing it (`GroupBoxes.parts`, `CueRowView.boxes`), refreshed on open, close, edits and `playlist_next`; a Name cell's text ends inside every box (`CueCell.textInset`).

## Meters (AUD-19, NFR-26)
- `WorkspaceStore.meters` (`MeterBank`) max-folds each `meters` push into preallocated per-source slots and publishes nothing.
- A `MeterView` registers only while on screen (in a window, not hidden or occluded). The bank's 60 Hz timer runs only while a view is registered. A push with no view registered is dropped.
- The bank holds views weakly; a view leaves it when its window closes or hides. Levels fall at a fixed dB/s and only changed views redraw.

## Custom views and buttons
- A custom `NSView` whose `draw(_:)` can paint outside its bounds (a line at an x off the visible span) clips first with `NSBezierPath.clip(bounds)`: `clipsToBounds` (available since macOS 10.9) defaults to false on the macOS 14 SDK, and clipping in `draw(_:)` gives the same result on every system whatever the SDK default. `WaveformView`, `MeterBank`'s meter, `LevelMatrixView` and the cue list's progress fill do.
- `Icon` (`Icons.swift`) is the one table of icons. Nearly every concept is openLab's own drawing: a 16-point SVG with a 1-point line in `Assets.xcassets/Icons/<name>.imageset` (`Icon.drawing`, names kebab-case: `kind-audio`, `state-broken`, `time-toggle-up`), loaded as a template image so it takes the tint. They are kept as plain SVG files so another platform can reuse them.
- Panic All draws its own picture (`Icon.fadeOut`); a few concepts are still SF Symbols (`Icon.symbol`: Active Cues' per-cue pause and resume, the engine alarm, a missing file's Target button), all from SF Symbols 1. A missing drawing or symbol is logged once and drawn as the label's text.
- Reset All, Pause All and Resume All share a circle outline; Active Cues' per-cue panic is the falling-curve drawing (the stopping mark's shape). The time headers' chevron points right while the column counts up and left while it counts down (`TimeHeaderCell.icon`).
- A `.texturedRounded` button's shape stays about 24 pt tall whatever its height; a button meant to be big uses `.regularSquare`, which fills it. The sidebar transport buttons are 44 pt with their icons drawn at 20 pt (`transportIconSize`, the vector drawing resized), and a test checks each icon fits the cell's content rect at default and minimum sidebar width.
- Tooltips wait 0.65 s (`ToolTipDelay`, owner decision; macOS's own wait is 1.5 s). `AppDelegate.main` registers it as the `NSInitialToolTipDelay` default before `NSApplication.shared`: AppKit's tooltip manager reads that key once, when the app object is made, as whole milliseconds (650; a fractional value is cut to 0), and a registered default leaves a value the user set winning.
- Every tip, the row status mark's broken reason, Warnings rows and inspector buttons included, is a plain `toolTip` shown by that manager; no view runs its own tooltip timer.
- The sidebar opens inside the least window (800x500): no inspector tab may need more width than the room left (its width less the sidebar's 280 pt), so none grows the window; a test opens it on every tab of every kind and checks the frame (`InspectorWindowFrameTests`). Time & Loops has two rows under the timeline (slices and zoom, then built-in fades) and its root stack fills; Triggers' rows wrap there (see below) and its hotkey field is 100 pt (its prompt truncates).
  - A Fade aimed at a Video cue: its Geometry tab's fields keep their width only below the window's hold on its size (they scroll instead), its thumbnail may shrink to 64 pt (drawn small, never hidden, so the picture's place still shows) and its note wraps at the fields' width.
- Active Cues rows (`ActiveCueCell`): the row stack distributes `.fill`, so the name and times column takes all the room between the buttons; with gravity areas it was as wide as its widest text and a lone time cut the name.
- A cue looping a slice with no end shows the time into its current pass in the Duration cell and in Active Cues alike (`LoopPass`). An Audio cue's Levels column (Mute and Gang on one row) fits the least window's inspector and scrolls only when the user shortens it; its scroll view has room for a legacy scroller.
- A looping Video cue held on its last frame after a devamp reports a position a microsecond short of the pass's end: the Duration cell then counts up (`loopPass` returns nil), as Active Cues does.
- The ruler's labels (`WaveformView.rulerMarks`): one under the start handle's triangle starts beside it, one under the end handle's is left out (its tick stays).
- Text that can be long never sizes the window: the masthead's standby name and the sidebar's list names truncate (lowest horizontal compression resistance), so the window keeps its width.
- Look rules (#775): the standby field's box is its line plus `standbyFieldInset` each side, and `MastheadMetrics.height` counts it, so descenders are not cut. A Duration cell's progress bar outlines the whole cell in the progress colour (green running, yellow paused) under the fill, so a playing cue stands out. An Active Cues tab with nothing playing shows `activeEmptyNote`.
- `TargetPathControl` shows an ellipsis item for the middle folders of a path that does not fit (home folder and file stay; the tooltip is the whole path). A window opened on a loaded store selects the playhead's cue (`followPlayheadAtOpen`), so the inspector shows it.
- The sidebar keeps its 280 pt whatever its tabs say: the tabs' horizontal compression resistance (240) is below the sidebar's preferred width (300) and the splits' holding priorities, so two-digit counts or a macOS with wider segmented controls give up the tabs' padding, then truncate, instead of widening the sidebar (`testTheSidebarKeepsItsWidthWhenItsTabsAreWider`). A drag stops at `SidebarViewController.minWidth` (250 pt), where the transport icons keep their margin.
- Cue list columns: Name changes width with the window; the three time columns keep their widths until Name would fall under `nameComfortWidth`, then give up width down to their least (header and the widest time the list shows, `h:mm:ss.cc` once a time reaches an hour; `fitTimeColumns`) and return to the widths they were given when there is room. A column the operator dragged keeps its width (the list scrolls sideways instead).
- A running time with no stored end (a looping group, a still Video cue held on screen) counts in the same widest-time rule: `longestTime` includes the Duration cell's shown running time, so the time columns widen once when a shown time reaches an hour (the progress refresh already runs the check per tick, and it lays out only when the answer changes) and narrow again when nothing shown or stored needs it, on a stop.
- A nesting level is `indentationPerLevel` (8 pt; the group boxes' text inset is taken from the room too) so a cue five groups deep still shows a letter at the least window.
- `fitNameColumn` sets Name to what the others leave (least `nameMinWidth`) on every layout and when another column is resized.
- It works from the scroll view's frame, always reserving a vertical scroll bar's width (some systems always show one), never from the clip view: the clip view's width changes as scroll bars come and go, and fitting to it can loop.
- Where scroll bars always show, the vertical bar stands over the right edge of the clip view (the clip view is as wide as the scroll view) and AppKit scrolls the columns clear of it: the list the operator sees ends at the bar, which is the room `fitNameColumn` reserves, so a test measures overflow against the bar's left edge, not the clip view's width.
- The sideways scroller is on only while the columns overflow that room. The list's least height and the window's least height each include a legacy scroller's height (`sidewaysScrollerHeight`), so at the least size with the scroller shown the one row is whole above it, and the shrink keeps the selected row in view.
- `fitNameColumn` also turns the sideways scroller on only while the columns are wider than that room (Name at its least): where scroll bars always show, a scroller kept for nothing covered the least list's one row. The vertical scroller is left as AppKit has it.
- No column is narrower than its header's text (`minWidth` from the header cell's `cellSize`; `TimeHeaderCell` adds its chevron), so a header never truncates; Name's least is the larger of that and `nameMinWidth`. Columns are never reordered (QLab only resizes them).
- The header row is `CueHeaderView`: a press on a column title tracks the mouse itself and reports a click on mouse-up over the same column (`onClick`, the time columns' switch), so no header is drawn pressed and none can be dragged. Only a press within AppKit's reach of a user-resizable column's right edge goes to `NSTableHeaderView`, which resizes it. The table delegate's `didClick` stays for accessibility presses.
- The header row is solid: `solidHeader` (on layout) has the clip view that holds the header draw the list's background. AppKit leaves a table header clear over a blur of the rows, and a list squeezed to one row (the least window with the inspector shown) showed the rows behind it through its titles. Overriding `CueHeaderView.draw` for this instead stopped the rows from drawing at all in a forced draw.
- Groups open and close without AppKit's slide (`CueOutlineView` runs `expandItem` and `collapseItem`, the triangle's click included, at zero animation duration): a column change while the slide ran (a resize, the sidebar or Show Mode toggled) never reached the rows outside it, whose cells stayed at the old columns, drawn over the new ones.
- A cue cell's label is a `WholeGlyphLabel`: it truncates at the tail and draws nothing where not even the first letter and the ellipsis fit (AppKit's own truncation draws a letter cut through there, in a deeply nested row at the least list width).
- A list made shorter (window, inspector or divider) scrolls its selected row into view (`keepSelectionInViewWhenShorter`) when the shrink cut off a selected row that was in view, as a selection change does; a list the operator scrolled away from the selection, or one that grows, is left alone.
- The in-place Name editor is at least `nameEditorMinWidth` wide, reaching over the columns to its right and kept inside the list, so a deeply nested row's name can be seen as it is typed; the field is a single scrolling line.
- The first column (`status`) has no title and a fixed width (`CueCell.statusWidth`, not resizable). Its cell lays its images out in fixed slots (`CueCell.statusSlots`): the playhead's room at the row's edge (0), the state (1), the cue-type icon (4; there is no type column), then one slot the preview or override mark (2) and the flag (3) share, the flag giving way (QLab shows a flag in its status area); the mark holding the slot then names the flag in its label and tooltip.
- No first-column mark moves when another appears, so every row's marks line up, indented rows included (indentation is in the Name column).
- A tinted mark is drawn in its colour, and in the selection's text colour (white) while its row is highlighted (`backgroundStyle` emphasized), as QLab draws a selected broken cue's mark.
- Mark colours (`CueStateStyle`, the cell's `fill`): running green; paused, loaded, fading, stopping and every warning (the Warnings list's marker, the footer's warnings count and warning status) `MarkColour.caution`, the system yellow on dark and a deeper golden yellow on light; broken (a red X; the triangle is for warnings only) and output-overridden red; flagged orange; preview blue.
- A cue in its pre-wait or post-wait shows the running mark, labelled with its wait (skill `qlab-behaviour` Q421, Q422). A paused cue's Duration-cell bar is the same caution yellow.
- The same fault is a Warnings row (`d:device_lost:<name>`, from the engine's workspace `warnings` notice) and goes when the device is back. Nothing about a warning is modal, in Show Mode too: the footer count and the open Status window change.
- A view-based table draws nothing for a row whose `viewFor` returns nil (`objectValueFor` is not used): every table gives each row a cell view. The sidebar's Cue Lists rows are `CueListNameCell`.
- The playhead is drawn by `CueRowView` (a triangle at the row's left edge, over the background and the selection); the status cell's playhead slot keeps the playhead's accessibility label. A closed group around the playhead shows nothing there (Q422). The list's style is `.fullWidth` so rows reach the window's edge.
- A row's tint is `CueKindStyle.shownColour`: the second colour once `store.played` holds the cue (the engine clears it on Reset All, a reset of the cue or its group, and a reopen), else the colour; a colour the app does not know is none. The active-cue stripe uses the same.
- `CueRowView.pattern` (`RowPattern.of`) is drawn over the tint and over the highlight, clipped to the row: `.disarmed` slanted lines, `.skipped` (disarmed with skip-if-disarmed) upright wavy lines.
- The masthead names the playhead cue as the engine reports it, a skipped one too (a GO there moves the playhead on and starts nothing; skill `qlab-behaviour` Q294, Q295).
- Time columns: `timeShown` per column, `.full` counts up while running, `.remaining` counts down; list times use `CueTime.running` (two decimals). `loopPass` gives a no-end cue's place inside its current slice from `progress.position`.
- A drag of cues shows `TargetDropOutline` over the hovered row's Target cell (`targetOutlineFor`): `.sets` in the cell, `.near` elsewhere on the row; removed on drop, drag end and when the drag leaves (`CueOutlineView.onDragExit`).
- `LevelsPanel`: `side` beside a scroll view whose `LevelsBoard` holds one vertical `LevelFader` per column over `LevelMatrixView` (value boxes, names, crosspoints). An Audio cue's `side` is buttons only (set default, set silent, Gangs, Clear Mutes, Edit Patch); a Fade keeps the chosen level's "fade this level". `layoutBoard` uses the scroll view's frame; `levelField` is laid over a box only while typing; `fader` is the chosen level's.
  - An Audio cue's `meter` is one `MeterView` across the board under the faders (`columns`): a bar just right of each cue output's fader (QLab 5 p. 204, Q589). It redraws only what is in view, takes no clicks and hides in gang mode. A Fade's tab has none.
  - All 128 cue outputs a patch can have are columns (`LevelSet.maxCueOutputs`), and `MeterBank` keeps 128 channels per source. Views are made only when the output count changes; scrolling makes none. An arrow key scrolls the chosen box into view.
  - `LevelSet` holds outputs to 128 and inputs to 64 and writes back untouched what it cannot hold (`unread`); only "set all silent" and "set defaults" clear it. A Fade's columns are its target's patch count (`levelExtent`).
  - A column the cue's levels do not list yet (its patch grew) is silent; a typed level or a Mute lists it (`set`, `setMute` pad to it), so the mute is kept.
- `MeterView` draws nothing for a source with no channels sent (unless `fixedRows`); in `columns` only the channels sent are drawn. In a light window the fader knob is drawn grey with an outline (`LevelFader.drawKnob`) and a value box is a light well (`LevelMatrixView.valueBoxFill`).
- Levels: a fader runs from the workspace's minimum to its maximum, 0 dB part-way. An unrouted crosspoint is an empty box. A mute is the box's right-click menu (`LevelMatrixView.menu(for:)`, an output or a routed crosspoint). Gangs is a toggle (`gangMode`): levels, faders and meters hidden, a letter typed in an output's box sets its gang (`commitText`). Clear Mutes is `.clearMutes`.
- `FadeCurveView` draws the engine's curve shapes (`shape` mirrors `Curve::shape`; keep the two equal). `TargetPathControl` shows a file target; `targetField` is hidden while it does.
- Show Mode locks list editing (`SidebarViewController.listEditLocked`): New List is off and `addList` refuses, the list menu's rename and delete are off and refuse; choosing a list stays on. Lists have no other create, reorder or delete path (no menu-bar item or key); there is no New Cart button (carts are not built).
- Sidebar Cue Lists rows are `ListRow`s: a list, or a cue of an open list (`openLists`). An assignment to `lists` in `init` runs no observer, so `init` calls `rebuildListRows` itself.
- Split observers (`startSavingLayout`) run from the window's start, file or not: a divider drag must update the soft size constraint or the divider springs back.
- `application(_:open:)` hands show files to `AppController.openFiles`, which holds them until `launchApplied`. New, Open and recents asked for before that wait in `afterLaunch` (no error alert) and run once `applyLaunchBehavior` ends; the launch choice itself uses `createWorkspace` / `openNow`. The document type is declared in `mac/project.yml` (`info.properties`); `verify-bundle.sh` checks it.
- A row-menu action must not share a selector name with a menu-bar action: the list's view controller is in the responder chain and would take the menu-bar item.
- `WorkspaceStore` drops `progress` items for cues whose state does not keep progress (`keepsProgress`): the engine sends no last empty `progress`, so an item taken for an ended cue would never clear.
- A `paused` cue with a reason (`device_lost`: its output device was lost while it played or waited; skill `devices`) draws the ordinary paused mark; `displayState` gives it the reason as its detail (the mark's tooltip, `ProblemText.pausedReason`), and the Warnings list words it for a paused cue (`ProblemText.reason(_:state:)`). Its time is the engine's frozen `progress` item. Resume on it is offered as for any paused cue (the engine clears the mark).
- The Warnings list (`WarningRows.make`) holds what is wrong now, once; the footer's count is its row count. The store keeps every warning the engine sends; the rows coalesce: a `cue_broken` refusal joins its cue's broken row as a count line (`warnings.refused.*`) and is dropped from the store once the cue is playable (no problems, no reason); another repeated warning is one row (key: its fields, `late_ms` aside) with its latest words and `warnings.repeated`.
- Device notices carry `device` (docs/protocol.md): one row per device and problem (`d:<family>:<name>`, `device_lost` and `patch_device_missing` one family), titled `warnings.device` with the name middle-cut at `deviceNameLength`, worded from the code (`warnings.device.<code>`), never the engine's `message`. The runtime `device_lost` notice is not listed: the one in the `warnings` list says the same and clears when the device is back.
- No internal id reaches the list: an id the model does not hold is `warnings.unknownItem`, a cue warning about a gone cue is titled `warnings.cueGone`, and ids in the engine text of a notice code that quotes item ids (`idQuotingNotices`: `load_repair`) are named (`ProblemText.namingIDs`); other notices' text (paths, volume names) is shown untouched. `WarningCell` wraps the title as well as the reasons, measured at the row's width.
- In-place list editing covers `preWait` and `postWait` too (`editableColumns`; not an auto-follow cue's post-wait, which shows its duration). A click in the continue column opens `continueMenu(row:)`.
- The cue-editing keys are keys of the workspace key map (`WorkspaceKey.editingActions`, `TransportKeys.editKey(for:)`, `EditKey`): a cell to open (`beginEditFromKey`), the notes (`beginNotesFromKey`: the inspector shown on Basics, caret in the notes), or C and F (`performEditKey`, `CueEditor.setProperty` on the selection). `AppController` tries them after the transport keys and before the cue hotkeys, never while text is typed.
- With several cues selected, E, D and W put the caret in the inspector's one field (`onEditSeveral`, `InspectorViewController.beginField`; nothing when the field is off for them, as an Audio cue's duration), and O in the shared notes; the value goes out through `commitBatch`, one transaction. N, Q and T open nothing.
- A committed cell edit keeps `cellEditor` over the cell (not editable, showing what was typed) until `onEditCell` returns, which is after the engine's answer and so after the model change: closed at commit it would uncover the old value for a moment. `settling` makes sure only the latest commit's answer closes it.
- The workspace status window (`StatusWindowController`, one per workspace window): pages Warnings (`WarningsPageController`: live `WarningRows`, pushed by `syncFooterWarnings`; no Check Again; Hide, Show hidden, Inspect Cue and Find Missing Files; a row selects its cue, the playhead stays), Logs (`LogWindowController`) and Info (name, id, file, Copy).
- The pages' controllers keep their lists but their own windows are never shown. Window > Workspace Status (Shift-Command-W), View > Warnings (Command-B) and the footer's warnings button or alarm open it; there is no Show Log command (Logs is a page).
  - Opening it never takes the keyboard (GO and the transport keys keep reaching the workspace), but a click on it does: it is a plain floating `NSPanel` (not non-activating), so the click makes openLab active and the window key and Command-W (File > Close, `performClose:` to the key window) closes only it.
  - While it is key it counts as its workspace's window: GO, the transport keys, cue hotkeys, Save and Esc panic act on that workspace (`frontController`; it is left out of `cueHotkeysBlocked`).
  - The sidebar has two tabs, Cue Lists and Active Cues.
- Workspace settings: a category list on the left (`SettingsCategory`: General, Controls, Audio, Video, Network) and the shown category's pages (`SettingsPage`; `+Pages`). The tab view (ids `general keys audio osc network video videoRouting videoDevices`) only holds the pages (`noTabsNoBorder`); the list and the page bar choose, `show(page:)` and `syncCategories()` keep them together.
- File > Workspace Settings has Settings Window (Command-comma) and each category's pages, which open the window on that page. Least size 680 x 552.
- General (`+General`): every box sends its setting (`WorkspaceSwitch` and `setSwitch`, auto-load's own command, number fields through `setNumber`) and the page is drawn from what the engine holds. Lock playhead (`CueListViewController.locksPlayhead`) stops a selection sending `set_playhead` and a runtime playhead move following; opening a window or switching list still selects the playhead's cue.
- Copying media into the show folder (WS-04, skill `media-files`): the General page's `copyMediaCheck` (`copy_media_on_add`, locked while `store.showMode`); File > Show Files > Copy Media into Show Folder, the submenu where QLab keeps it (`AppDelegate.copyMediaIntoShowFolder`, `WorkspaceWindowController+CopyMedia`: on only for a saved show in Edit Mode with no on-demand copy running, `canCopyMedia`).
  - The store keeps `copyingMedia` (from `media_copy_progress`) and sends each `media_copied` on `mediaCopied`.
  - A file cue's Target cell draws `Icon.targetFileCopying` (caution colour) while its file is copied; its tooltip names the cue's file under the label. A copy's end is a footer notice (`MediaCopyNotice`: on demand always, on add only with failures or stopped), failures by cue number, file name and reason in its tooltip and the show log; never an alert (a copy may end in a show).
  - The Save panel's accessory (`SaveTarget.choicePopup`) offers a new show folder with the media (chosen first while the setting is on) or the show file only; `pickSaveURL` answers a `SaveTarget`. The folder option makes `<dir>/<name>` (numbered if taken, off the main thread), saves the show inside and sends `copy_media`. The bundled test shows hold the setting off.
- Key up before the next GO (`AppController.goKeysDown`): a GO-key press with no release since the last is taken and fires nothing; cleared on key-up and when the app is left. The GO button shows a red border while the engine says `go_protection` is active (`MastheadView.setGoProtection`) and the area behind it flashes once per ignored GO (`goBlockedCount`, `flashGo`); a `go_ignored` of reason `double_go` is not listed as a warning.
- The OSC page (`+Osc`, `WorkspaceSettingsModel+Osc`): the access switch (`osc_enabled`), the listening port with whether it is open and why not (`osc_state`, `set_osc_port`), this Mac's IPv4 addresses (`LocalAddresses`). A port the engine cannot open is refused with the old one still listening; the page says so in its status line and the message row.
- Launcher (`LauncherWindowController`; resizable, least 560x380): left column app icon, version, New Workspace and Open Workspace; right column Recent Workspaces (name over folder, newest first, at most 10; a missing file stays listed, marked: the system's recent list drops a deleted file, so the app keeps what it listed in `launchDefaults` (`rememberedRecents`) until Remove from List; a moved file is followed by the system); empty state a line and a hint.
- Launcher state comes from `AppController.bindLauncher`: starting (spinner, New/Open/list disabled), failed (reason and "quit and reopen"), ready. A double-click or Return on a recent opens it; one whose file is gone raises a notice with Remove from List and the launcher stays.
- No launcher help link until the project has a page. Application preferences, General tab: the launch choice and how many backups of each workspace this machine keeps (`backup_keep`, `set_backup_keep`; 0 turns backups off). The autosave interval is the workspace's (General page of the workspace settings, 5 s to 1 h), as it is stored in the show.
- The Video pages (`VideoSettingsPane.swift`, one instance per `VideoSettingsPane.Section`; commands in `Engine/StageCommands.swift`) are split as QLab 5's Video settings are, only for what openLab has (no Video Inputs: no camera cues). All three are in `SettingsCategory.video` and its page bar.
  - Video Outputs (page `video`, `videoPane`): a grid of the workspace's stages: name typed in place, pixel size (width and height fields, 1 to 16384, refused in the page with a line; one `size` edit), keep-black box, layer field (0 to 1000, refused in the page with a line), Monitor, remove; New Stage above.
  - Output Routing (`videoRouting`, `videoRoutingPane`): per stage its name, size and the display pop-up (this machine's choice: `set_stage_mapping`), with the stage's warning under the row.
  - Output Devices (`videoDevices`, `videoDevicesPane`): the displays this Mac has with their size and the stages shown on each, read-only.
- Settings tables share the window's width and never set its least size: a table's columns are fitted to the width the page is given (Name and Address on Network Outputs, Name and the display column on the Video pages), and the grid's trailing edge is pinned at priority 250, never required, so a page laid out wide cannot hold the window wide. Every page, Interface and remove included, fits at 680 pt without a scroller.

- Load to Time (`LoadTimeBarView`, `+LoadTime`): Cmd-T cycles the bar (open in the cue-type row's place; cursor in its field; closed, list focused). A time typed (Return; a minus counts back from the end of the sequence, `CueTime.parseSigned`) or the slider let go sends `load` for the playhead cue (`standingByCue`); the engine loads its sequence.
- The bar's slider spans the engine's `sequence_span` (off when unknown), re-asked only when the standing-by cue, `store.revision` or `mediaDurationsVersion` changes (`LoadTimeState.spanFor`); a new standing-by cue clears the bar. The knob follows a negative time; text that is not a time reverts to the last time loaded. On in Show Mode. Any loaded cue's Duration shows `loadedAt.time` (`loadedStand`; no fill without a length).
- A fading cue's state mark is `PulsingDots` (a ring of eight dots round a ring of four that stand still while a brightness sweeps clockwise round them every 0.8 s, on one shared 30 Hz ticker that runs only while a dots view is shown; still with Reduce Motion), over state image 1, which keeps the label and tooltip (owner's request 2026-11-22).
- Toolbar buttons are `CueToolbarButtons`: a press that moves starts a drag carrying `CueToolbarView.dragType`; the list proposes a place (`setDropItem`: the outline draws its own insertion line) and `onKindDrop` adds the cue there (`CueEditor.add(_:at:)`). A press that does not move is a click, delivered through `onClick` with its segment (a momentary control reads no selected segment once its tracking ends). Off in Show Mode.
- Renumber takes start, increment, prefix and suffix and the engine skips numbers cues outside the selection hold. Select Cue's sheet has a Playhead button (`AX.cuePromptPlayhead`). View: sidebar tab switch, next / previous sequence (`=`, `-`), Enter Full Screen; File > Show Files: Copy Media into Show Folder, Show Workspace in Finder; Tools: Paste Levels.
- A cue with no name and no default name has an empty Name cell; default names (`fade intro`, `wait 00:05.00`) are lower case.

- About (`AboutWindowController`, the app menu's item, `AppController.aboutWindow`): a fixed-size, non-modal window of icon, name, the bundle's version and build (`AboutWindowController.version`, also the launcher's), description and licence line; no links or buttons (owner 2026-11-20). Esc still panics first, then closes it.

## Seeing the app
- `make ui-shots SCENARIO=mac/scenarios/<name>.json [OUT=<dir>]` drives the real workspace window on the real engine (stepped virtual clock) and writes `<OUT>/<nn>-<name>.png` per shot plus `steps.log` (each step and what it hit). OUT defaults to `build/ui-shots/<name>`. It builds for testing only when `mac/` app, test, test-show or project files or the engine changed since the last build; editing a scenario needs no build.
- The runner is `ScenarioRunner` in `mac/openLabTests` (test-only, never in a Release product). The window is never ordered on screen or made key: it takes no focus and never moves the pointer, so it runs while the user works. It takes the same machine-wide lock as `make prepush`'s UI tests (`lockf /tmp/openlab-xcuitest.lock`), so it waits for another mac test run. Never run it under another `lockf` on that file: the nested lock waits forever.
- Presses go to the view under the point with the window's press hook; a standard control in a window that is not key ignores `mouseDown`, so its cell tracks the press instead. A press on a pop-up button is refused (its menu needs real input): use `choose`, `open_menu`.
- Keys go through the app's own key handling (`AppController.handleKeyDown`, Esc's panic sent to the engine), then a key equivalent, then the window. Cue hotkeys and menu-bar commands are not reached. GO moves the selection to the next cue, so select the playing cue again to inspect it.
- Shots render the window's frame view offscreen at 2x with `displayIgnoringOpacity` (the shared `renderView`): every view draws with the clip AppKit gives it on screen, so a view that does not clip to its bounds shows its overdraw. Forced to draw, a tab view paints a blank white bar over its tabs; `renderView` paints the tab buttons again over it. `cacheDisplay` skips layer-backed subviews; do not use it for pictures.
- Scenario: `show` (a `mac/TestShows` name, `new` for a new untitled workspace, or a `.openlab` path relative to the scenario, opened in place and never saved), optional `media` (`{"media/a.wav": seconds}`: written into a test show's copy first by extension, a test tone, a movie `.mov`/`.mp4` or a still `.png`/`.jpg`/`.tiff`), `window` (`{"width", "height"}`, points, default 1200x800), `appearance` (`dark` default, or `light`), `about` (free text), `steps`.
- A movie in `media` gets audio tracks with `{"seconds": n, "sound": "pcm:2:48000+pcm:6:44100"}` (one per `+` part) in place of the number.
- Steps, one action key each: `select` (cue number, else name, or a list of them selected together); `click` / `double_click` / `drag` (an accessibility identifier; `at`, `from`, `to` as `[x, y]` fractions of the control from its top-left; `modifiers`); `type` (identifier, `text` replacing what the field holds, `""` empties it; `enter` default true).
- More steps: `key` (one character or space, escape, return, tab, delete, left, right, up, down; `modifiers`: shift, control, option, command); `scroll` (identifier; `dx`, `dy`, `precise` default true, `modifiers`, `at`); `magnify` (identifier, `by`, `at`);
  `advance` (seconds of device time, run in tenths); `device` (`lose`: a virtual output unplugged; `restore`: listed (again), opened at the engine's next list read, so `advance` about 2 s after it; `default`: made the system's output from that read; `output` 1, the default, or 2, the second, listed only once restored); `resize` (`[width, height]`); `tab` (inspector tab identifier, or the settings tab while the settings window is focused); `shot` (name).
- `tool` (`load_to_time`: Tools > Load to Time cycles the bar).
- `inside` (an identifier, `of`: another): the run stops unless the first lies inside the second (a tab view: its content, below the tabs), as laid out at that step.
- `focus` (`settings`: the workspace settings window, opened without taking focus, is the window the next steps and shots act on, its devices and patch resolutions read again before each shot, as the visible window rereads them on an output's change; `patch-editor`: the editor a click on `settings-patch-edit-N` opened, drawn off screen (`presentsEditors` false)).
- `focus` `about` draws the About window off screen.
- `focus` `launcher` draws the launcher off screen: `recents` (names; a leading `!` is a missing file), `state` (`ready`, `starting`, `failed`), `notice` (true: the missing-file notice), `size` (content size; its least is 560x380).
- `focus` also takes (`status`: the workspace status window drawn off screen, its pages chosen with `tab` (`warnings`, `logs`, `info`); `workspace` goes back).
- `paste_properties` (a cue number: that cue copied to a private pasteboard and Paste Properties opened for the selection; `tick`: property names). The sheet is never put on screen (`presentSheet`); shots draw it over the window, centred under the title bar. A second step cancels a sheet still up. `focus` `sheet` sends the next `click` (its `paste-property-*`, `paste-category-*`, `paste-properties-apply`/`-cancel`) and `key` steps to the sheet; once it closes the steps go back to the workspace.
- `open_menu` (a pop-up button's identifier): its menu shown open in the next shots, items listed in `steps.log` too (`[x]` chosen, `(off)` disabled; a pull-down's title item left out). A disabled or empty pop-up stops the run. Drawn from the items, not AppKit's menu. Any step but a shot or `advance` closes it; `choose` picks from it.
- `hover` (identifier, `at`; or `header`/`row` as below): the next shots draw the tooltip as a bubble drawn by the runner, not AppKit (a view's, a segment's from the rectangles AppKit's accessibility elements give its segments, a column header's). No tooltip there stops the run. Any step but a shot or `advance` ends it.
- `menu_command` (`undo`, `redo`, `delete`, `cut`, `copy`, `paste`): the Edit item's action sent from the window's first responder up the chain, then to the app's menu actions. An item the menu greys out, or text being edited (first responder an `NSText`), stops the run.
- `shot` takes `display` (a virtual display id from `displays`, or a list): `<n>-<name>-display-<id>.png` beside the window shot, the display's composite read back with the stage host's test probe at about 1000 points and drawn as 8-pixel blocks.
- `shot` takes `monitor` (a stage's name; `monitor_size` `[w, h]` pixels, default the size it opens at): `<n>-<name>-monitor.png`, that stage's monitor window read back the same way (`monitor_probe`); a monitor not open stops the run.
- `drag` takes `header` (a column's title, or its identifier where it has none), `hover` takes `header` or `row` (a cue's number or name), on a table such as `cue-list`: fractions are of that header cell or row. A drag may go past the cell but must stay inside the header view.
- `drag` also takes `row` (a cue's number or name) with `to_row`: the row dragged onto another named row. No AppKit drag session (it needs real input): the outline is fed entered, updated and perform with a stand-in dragging info ending at `to` (fractions of the target row), so the proposed drop (above, below, into an open group, onto a Target cell) is AppKit's.
- A `drag` drop the list refuses (Show Mode, a group onto itself) is logged `refused`, not a failure. `steps.log` gives the resulting order and targets. An unknown name stops the run.
- `steps.log` gives a header drag's column width before and after.
- `hover` also takes `segment` (a segment's tooltip, else its label) of a segmented control inside the view, such as `cue-toolbar`: fractions are of that segment as AppKit lays it out.
- `set_media` (a cue, `file`: its file reference set as an edit; a file that is not there leaves the cue missing it).
- `choose` (a pop-up button's identifier, `item`: that item picked as from its menu, which is never opened). `find_missing_files` (paths of test tones written into a folder, named by `folder`, default `found`): Find Missing Files searches it, off screen; the next steps and shots act on the tool's window (`missing-files-*` identifiers; its list scrolls through `missing-files-scroll`), `focus` `sheet` on its question (`missing-file-choice-*`), drawn over it.
- A step that cannot be done stops the run with a reason and a non-zero exit: an unknown or repeated identifier (the identifiers shown are listed), a disabled control, a press that lands on another view, a cue or tab not found. Reusable scenarios live in `mac/scenarios/`.

## Build
- `.xcodeproj` is generated by XcodeGen from `mac/project.yml`, never committed.
- The engine is built universal (arm64 + x86_64 via `lipo`) by a build-phase script calling `cargo`.
- The stage host (video output windows, skill `video`) is built the same way by `mac/scripts/build-stage-host.sh` into the helper app `Contents/Helpers/openLab Stage.app` (bundle id `dev.openlab.openLab.stage`, `LSUIElement`, minimum 12.0), signed inside-out before Xcode signs the app; Debug builds it with `test-support`. The engine finds it there.
- Release: `make mac`, then `make verify-bundle` (universal, macOS 12.0 on every slice, no test-only code, the app's version equal to the bundled engine's `--version`, the `AppIcon` present, a valid signature; the stage host helper universal, 12.0, signed and `LSUIElement`; the engine linking no AppKit, Metal or QuartzCore; release engine and stage host refusing `--virtual-displays`).
- `make dmg` writes `build/openLab-<version>.dmg`: the app, an Applications link, `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt` (no Finder window layout: setting it needs AppleScript against a live Finder, which is flaky on CI runners).
- `scripts/third-party-notices.py generate` rewrites the repo-root `THIRD-PARTY-NOTICES.txt` from the dependency graph of the engine and stage host (run it when `engine/Cargo.lock` changes); `make lint` (check-repo) and `make verify-bundle` fail if a shipped crate is missing from it.
- The notices and `LICENSE` are copied into the app's Resources (`mac/project.yml`); the About window lists no components.
- The app inside is named `openLab <version>.app` so versions install side by side (DST-03). The version is `MARKETING_VERSION` in `mac/project.yml` and `version` in `engine/Cargo.toml`, changed together; `CHANGELOG.md` gets an entry.
- The app icon is `mac/openLab/Assets.xcassets/AppIcon.appiconset`, scaled from `mac/Branding/openlab-logo-1024.png`.
- The app is not sandboxed (it spawns the engine and opens arbitrary media paths). Hardened runtime and notarisation need an Apple Developer account; ad-hoc signed until then.
- Inspector tabs: the `NSTabView` is `.noTabsNoBorder`; `InspectorTabBar` above it draws one flat `InspectorTabButton` per tab at the left, each as wide as its whole title, in a scroll view (the wheel scrolls it sideways) that brings the chosen tab into view. `syncTabBar` follows `syncTabs`; `tabView(_:didSelect:)` follows a choice.
- A Group's Mode tab is one radio per mode (`groupModeRadios`) with the chosen mode's name and a line saying what it does beside them; Loop and Shuffle are drawn only for a playlist (`showGroupModes`). A Network cue's Settings tab is the patch row (pop-up, Send) over a message area filling the tab's width and height.
- Every inspector time field shows milliseconds (`CueTime.precise`: `00:01.000`); the cue list keeps hundredths. A file cue whose file is missing or unplayable shows `inspector.target.fileMissing` or `fileUnsupported` beside its target (`targetNote`, the engine's problem in its tip).
- Time & Loops: Delete Slices and New Slice (New Slices while a section is selected) are in the left column under the play controls; reset (ends a preview) and preview sit under the timeline beside zoom (`TimeLoopsPanel.showPreview`). A ruler label that would run past the view's edge is left out, never drawn cut.

- Every `isFlipped` override is `nonisolated` (a constant): AppKit asks it from its display cycle, and the Swift 6 executor check an isolated override gets crashed the app there (#795 S5; `scripts/check-repo.sh` enforces it).
- Every alert, sheet and panel goes through `StandBack.swift` (`StandBack.runModal`, `StandBack.beginSheet`; `AppController.alerts` wraps any `WorkspaceAlerts` in `StandingBackAlerts`); `scripts/check-repo.sh` fails on a site that does not. While one is up the stage and the app's black on the display with the menu bar stand back (skill `video`), so the operator sees it; Esc keeps AppKit's behaviour (a Cancel button takes it; an OK-only alert has none) after the key monitor's panic.
- The engine alarm (`EngineAlarmPanel`) and the notes notice (`NotesNoticePanel`) are standard `NSAlert` windows (`FloatingAlert`: critical style and app icon for the alarm, bold message, informative text, the detail as the accessory) shown without running them modally, with our own button actions. They float, never become key on their own (`becomesKeyOnlyIfNeeded`, text not selectable) and block nothing, so GO and Esc keep working.
  - The offer of autosaves after an unclean end is the same alert, ordinary style, with Restore Autosaves… and Not Now.
  - OutputOverrides is a palette (`NonKeyPanel`) and the media-copy notice a footer line, not alerts.
