# macOS app structure

Must not break: view controllers never touch the socket; Show Mode never opens an alert or sheet except the modal cases listed below; meters publish nothing while no `MeterView` is on screen.

Stack rules (Swift 6, AppKit, macOS 12.0, no SwiftUI/Observation/third-party packages, SF Symbols, `Localizable.strings`) are in CLAUDE.md.

## Chain
- `EngineClient` (socket, reconnect, message codec; `URLSessionWebSocketTask`, `Codable`) -> `WorkspaceStore` (mirrored model and runtime state, publishes changes) -> AppKit view controllers.
- View controllers never touch the socket.
- One window per open workspace, each with its own `EngineClient` bound to that doc (`hello { workspace }`) and its own `WorkspaceStore`.
- An app-level session holds the unbound connection and owns launch, New/Open/recovery flows, the workspace list, recent files and the quit walk (one save prompt per dirty workspace).
- The front window decides which doc GO, Pause All and other window-scoped keys address. Esc sends the app-scope `panic`.
- Edit > Undo and Redo act on the workspace whose window or settings window is key (`AppController.undoController`), so a settings change (the OSC passcode table, NET-02) is undone from the settings window; every other window-scoped key still needs the workspace window itself.
- Closing a workspace while cues play asks first. Closing the last one shows a launcher window.
- No `NSDocument` subclass. UI is built in code: no storyboards or XIBs, main menu included.
- Main window layout follows QLab 5 (UI-07): toolbar and GO area on top, cue list (`NSOutlineView`, view-based, cell reuse for 2,000+ cues) centre, sidebar, tabbed inspector below. Dark appearance by default.

## Meters (AUD-19, NFR-26)
- `WorkspaceStore.meters` (`MeterBank`) max-folds each `meters` push into preallocated per-source slots and publishes nothing.
- A `MeterView` registers only while on screen (in a window, not hidden or occluded). The bank's 60 Hz timer runs only while a view is registered. A push with no view registered is dropped.
- The bank holds views weakly; a view leaves it when its window closes or hides. Levels fall at a fixed dB/s and only changed views redraw.

## Custom views and buttons
- A custom `NSView` whose `draw(_:)` can paint outside its bounds (a line at an x off the visible span) clips first with `NSBezierPath.clip(bounds)`: `clipsToBounds` (available since macOS 10.9) defaults to false on the macOS 14 SDK, and clipping in `draw(_:)` gives the same result on every system whatever the SDK default. `WaveformView`, `MeterBank`'s meter, `LevelMatrixView` and the cue list's progress fill do.
- `Icon` (`Icons.swift`) is the one table of icons. Cue kinds and Group modes are openLab's own drawings: 16-point SVGs with a 1-point line in `Assets.xcassets/Icons/<name>.imageset` (`Icon.drawing`), loaded as template images so they take the tint. They are kept as plain SVG files so another platform can reuse them. Every other icon is an SF Symbol row with a fallback. A missing drawing or symbol is logged once and drawn as the label's text.
- A `.texturedRounded` button's shape stays about 24 pt tall whatever its height; a button meant to be big uses `.regularSquare`, which fills it. The sidebar transport buttons are 44 pt with 18 pt symbols, and a test checks each symbol fits the cell's content rect at default and minimum sidebar width.
- Text that can be long never sizes the window: the masthead's standby name and the sidebar's list names truncate (lowest horizontal compression resistance), so the window keeps its width.
- Cue list columns: only Name changes width with the window; the others keep theirs, so the times stay whole down to the least window width. `fitNameColumn` sets Name to what the others leave (least `nameMinWidth`) on every layout and when another column is resized. It works from the scroll view's frame, always reserving a vertical scroll bar's width (some systems always show one), never from the clip view: the clip view's width changes as scroll bars come and go, and fitting to it can loop.
- A view-based table draws nothing for a row whose `viewFor` returns nil (`objectValueFor` is not used): every table gives each row a cell view. The sidebar's Cue Lists rows are `CueListNameCell`.
- The playhead is drawn by `CueRowView` (a triangle at the row's left edge, over the background and the selection); the status cell keeps an empty slot with the playhead's accessibility label. The list's style is `.fullWidth` so rows reach the window's edge.
- A row's tint is `CueKindStyle.shownColour`: the second colour once `store.played` holds the cue (the engine clears it on Reset All, a reset of the cue or its group, and a reopen), else the colour; a colour the app does not know is none. The active-cue stripe uses the same.
- `CueRowView.pattern` (`RowPattern.of`) is drawn over the tint and over the highlight, clipped to the row: `.disarmed` slanted lines, `.skipped` (disarmed with skip-if-disarmed) upright wavy lines.
- The masthead names `WorkspaceModel.firstPresent(from:)` of the playhead: the playhead cue, or past a skipped one the next cue there along its level, then outwards (core's `first_present`), so it names what GO starts. The playhead mark stays on the cue the engine reports.
- Time columns: `timeShown` per column, `.full` counts up while running, `.remaining` counts down; list times use `CueTime.running` (two decimals). `loopPass` gives a no-end cue's place inside its current slice from `progress.position`.
- A drag of cues shows `TargetDropOutline` over the hovered row's Target cell (`targetOutlineFor`): `.sets` in the cell, `.near` elsewhere on the row; removed on drop, drag end and when the drag leaves (`CueOutlineView.onDragExit`).
- `LevelsPanel`: `side` (buttons, the chosen level's mute/gang or "fade this level") beside a scroll view whose `LevelsBoard` holds one vertical `LevelFader` per column over `LevelMatrixView` (value boxes, names, crosspoints). `layoutBoard` works from the scroll view's frame. `levelField` is laid over a box only while typing (`beginTyping`). `fader` is the chosen level's fader.
- Cue outputs above 64: a patch can have 128, but the Levels and Fade tabs show only the first 64 columns (`LevelMatrixView.maxShownOutputs`) and `MeterBank` keeps only 64 channels per source. `LevelSet` holds outputs to 128 and inputs to 64, and writes back untouched what it cannot hold (`unread`), so an edit never drops routing the tab does not show; only "set all silent" and "set defaults" clear it.
- `FadeCurveView` draws the engine's curve shapes (`shape` mirrors `Curve::shape`; keep the two equal). `TargetPathControl` shows a file target; `targetField` is hidden while it does.
- Sidebar Cue Lists rows are `ListRow`s: a list, or a cue of an open list (`openLists`). An assignment to `lists` in `init` runs no observer, so `init` calls `rebuildListRows` itself.
- Split observers (`startSavingLayout`) run from the window's start, file or not: a divider drag must update the soft size constraint or the divider springs back.
- `application(_:open:)` hands show files to `AppController.openFiles`, which holds them until `launchApplied`. The document type is declared in `mac/project.yml` (`info.properties`); `verify-bundle.sh` checks it.
- A row-menu action must not share a selector name with a menu-bar action: the list's view controller is in the responder chain and would take the menu-bar item.
- `WorkspaceStore` drops `progress` items for cues whose state does not keep progress (`keepsProgress`): the engine sends no last empty `progress`, so an item taken for an ended cue would never clear.
- In-place list editing covers `preWait` and `postWait` too (`editableColumns`; not an auto-follow cue's post-wait, which shows its duration). A click in the continue column opens `continueMenu(row:)`.
- The cue-editing keys are keys of the workspace key map (`WorkspaceKey.editingActions`, `TransportKeys.editKey(for:)`, `EditKey`): a cell to open (`beginEditFromKey`), the notes (`beginNotesFromKey`: the inspector shown on Basics, caret in the notes), or C and F (`performEditKey`, `CueEditor.setProperty` on the selection). `AppController` tries them after the transport keys and before the cue hotkeys, never while text is typed.
- A committed cell edit keeps `cellEditor` over the cell (not editable, showing what was typed) until `onEditCell` returns, which is after the engine's answer and so after the model change: closed at commit it would uncover the old value for a moment. `settling` makes sure only the latest commit's answer closes it.
- Workspace settings tabs: General, Keys, Audio, OSC, Network. General's "new cues load ahead" box (`+General`) sends `setNewCuesAutoLoad`; the engine ticks auto-load on cues made afterwards.
- Basics colours: two image-only pop-ups of `colourItems` (none, eight basic, twelve extended, separators between; each item's `representedObject` is the colour, its image `CueKindStyle.swatch`). The second sits behind `secondColourCheck`: ticked it unlocks the menu (`secondColourUnlocked` until a pick), unticked it sets `second_color` none.
- A column of a tab ends with `columnFiller()`, which takes the height the tab stretches it to; without it the last control slid to the bottom.
- Triggers: `hotkeyEnableCheck` is the hotkey trigger's switch (one cue at a time). It shows the stored `hotkey_enabled` with or without a key, so it can be ticked before the key is typed; a recorded key keeps the switch it shows. Off keeps the key, drawn faint; on again with a key is checked with `HotkeyRules` and refused when the key is now another's. `cueHotkeys` lists only keys that are on (they fire and clash); `storedCueHotkeys` every key, for the key map.
- The Triggers tab's right side (`InspectorOthers.swift`): fade out and stop others (box, scope, time) and duck or boost others (box, dB, time), each edit changing only its part of each cue's own setting. The times and the dB are `InspectorField`s; the dB is `OthersLevel` (a plain number boosts). The box reads boost above 0 dB, relabelled as the number is typed. Off, the values are kept and drawn off.
- `triggers`, `fade_and_stop_others` and `duck_others` are replaced whole: an edit sent before the last one is answered builds on `pendingWholes` (a transaction's included), never on the stale model.
- Keys (`+Keys`) is the key map: workspace and cue-editing actions in two columns, each a `HotkeyRecorder`, a clear button and a reason line beside it (`KeyRefusal`, one at a time). It refuses what the engine would (another action's key, a cue's hotkey, Esc, Up/Down) and takes a menu command's key, which then warns (Q80).
- The Network tab (`+Network` files) is a grid of destinations drawn from the model like the OSC table; files added to `mac/openLab` need `make project` before a build sees them.
- `WorkspaceWindowController` removes its split observers in `windowWillClose` (`stopSavingLayout`), and their blocks hold the split weakly: a block-based observer left in the notification centre keeps what it captured for the life of the app, and every closed window's view tree stayed alive. `testAClosedWindowsViewsAreReleased` guards it.
- The row menu's Edit submenu (`editSubmenu`, `RowEdit`) sets one property on `rowMenuCues` through `CueEditor.setProperty(_:of:)`, one transaction. The Audio I/O tab is `InspectorIO.swift`; the patch goes out as `kindFields(["patch": id])`.
- Several cues selected (`InspectorBatch.swift`): `render` draws them with `renderBatch`, the tabs `batchTabs(forKinds:)` gives (Basics and Triggers for mixed kinds). A value that differs shows as mixed (`showChoice`'s hidden Mixed item, `showTicks`, `LevelsPanel.mixed`).
- Edits of several cues go to `editCues` through `sendEach` / `sendKindEach` / `commitBatch` as one transaction; a typed field is sent only if typed.
- A levels edit on several cues is replayed on each cue's own levels (`LevelsPanel.lastEdit`, `LevelSet.taking`: the one level moved with that cue's own gang, a mute, a gang, set silent or defaults), never copied whole; gangs that differ are not drawn or set (`gangsMixed`).
- With several cues shown (`editsSeveral`) an action is reported even when the first cue already has its result. A mixed level's fader draws no knob (`LevelFader.isMixed`). Notes refused for several cues are offered back as one cue's are. `endBatchControls` restores one cue's controls.
- Paste Properties (Edit menu, row menu, Shift-Command-V): `PasteProperty` holds the categories (Basics also the second colour, load ahead, skip; Triggers the others' fade and duck), which kinds take each and the commands; `PastePropertiesSheet` is the sheet, its ticks remembered in `pasteDefaults` at Apply. `promptPasteProperties` opens it for the selection of that moment; `CueEditor.pasteProperties` sends one transaction. Off in Show Mode, which cancels a sheet that is up.
- The sheet's window (`PasteSheetWindow`) takes Up, Down, Space, Return, Enter and Esc itself, before any control and whatever the keyboard setting: a highlighted row (`PasteSheetRow`), Space ticks it (a category row: the category). A sheet as key window blocks cue hotkeys (`cueHotkeysBlocked`); Esc still panics first. The title is one line, the cue's label cut in the middle.
- A trim handle drawn at an edge of the waveform is moved inside it so it is whole (`drawHandle`). The playhead, slice and insertion lines are not: at the very edge the clip cuts half their width.

## Seeing the app
- `make ui-shots SCENARIO=mac/scenarios/<name>.json [OUT=<dir>]` drives the real workspace window on the real engine (stepped virtual clock) and writes `<OUT>/<nn>-<name>.png` per shot plus `steps.log` (each step and what it hit). OUT defaults to `build/ui-shots/<name>`. It builds for testing only when `mac/` app, test, test-show or project files or the engine changed since the last build; editing a scenario needs no build.
- The runner is `ScenarioRunner` in `mac/openLabTests` (test-only, never in a Release product). The window is never ordered on screen or made key: it takes no focus and never moves the pointer, so it runs while the user works. It takes the same machine-wide lock as `make prepush`'s UI tests (`lockf /tmp/openlab-xcuitest.lock`), so it waits for another mac test run. Never run it under another `lockf` on that file: the nested lock waits forever.
- Presses go to the view under the point with the window's press hook; a standard control in a window that is not key ignores `mouseDown`, so its cell tracks the press instead. A pop-up button is refused (its menu needs real input).
- Keys go through the app's own key handling (`AppController.handleKeyDown`, Esc's panic sent to the engine), then a key equivalent, then the window. Cue hotkeys and menu-bar commands are not reached. GO moves the selection to the next cue, so select the playing cue again to inspect it.
- Shots render the window's frame view offscreen at 2x with `displayIgnoringOpacity` (the shared `renderView`): every view draws with the clip AppKit gives it on screen, so a view that does not clip to its bounds shows its overdraw. Forced to draw, a tab view paints a blank white bar over its tabs; `renderView` paints the tab buttons again over it. `cacheDisplay` skips layer-backed subviews; do not use it for pictures.
- Scenario: `show` (a `mac/TestShows` name, `new` for a new untitled workspace, or a `.openlab` path relative to the scenario, opened in place and never saved), optional `media` (`{"media/a.wav": seconds}`: a test tone written into a test show's copy first), `window` (`{"width", "height"}`, points, default 1200x800), `appearance` (`dark` default, or `light`), `about` (free text), `steps`.
- Steps, one action key each: `select` (cue number, else name, or a list of them selected together); `click` / `double_click` / `drag` (an accessibility identifier; `at`, `from`, `to` as `[x, y]` fractions of the control from its top-left; `modifiers`); `type` (identifier, `text`, `enter` default true).
- More steps: `key` (one character or space, escape, return, tab, delete, left, right, up, down; `modifiers`: shift, control, option, command); `scroll` (identifier; `dx`, `dy`, `precise` default true, `modifiers`, `at`); `magnify` (identifier, `by`, `at`); `advance` (seconds of device time, run in tenths); `resize` (`[width, height]`); `tab` (inspector tab identifier, or the settings tab while the settings window is focused); `shot` (name).
- `focus` (`settings`: the workspace settings window, opened without taking focus, is the window the next steps and shots act on; `workspace` goes back).
- `paste_properties` (a cue number: that cue copied to a private pasteboard and Paste Properties opened for the selection; `tick`: property names). The sheet is never put on screen (`presentSheet`); shots draw it over the window, centred under the title bar. A second step cancels a sheet still up. `focus` `sheet` sends the next `click` (its `paste-property-*`, `paste-category-*`, `paste-properties-apply`/`-cancel`) and `key` steps to the sheet; once it closes the steps go back to the workspace.
- A step that cannot be done stops the run with a reason and a non-zero exit: an unknown or repeated identifier (the identifiers shown are listed), a disabled control, a press that lands on another view, a cue or tab not found. Reusable scenarios live in `mac/scenarios/`.

## Build
- `.xcodeproj` is generated by XcodeGen from `mac/project.yml`, never committed.
- The engine is built universal (arm64 + x86_64 via `lipo`) by a build-phase script calling `cargo`.
- Release: `make mac`, then `make verify-bundle` (universal, macOS 12.0 on every slice, no test-only code, the app's version equal to the bundled engine's `--version`, the `AppIcon` present, a valid signature), then `make dmg` writes `build/openLab-<version>.dmg`. The app inside is named `openLab <version>.app` so versions install side by side (DST-03). The version is `MARKETING_VERSION` in `mac/project.yml` and `version` in `engine/Cargo.toml`, changed together; `CHANGELOG.md` gets an entry.
- The app icon is `mac/openLab/Assets.xcassets/AppIcon.appiconset`, scaled from `mac/Branding/openlab-logo-1024.png`.
- The app is not sandboxed (it spawns the engine and opens arbitrary media paths). Hardened runtime and notarisation need an Apple Developer account; ad-hoc signed until then.
