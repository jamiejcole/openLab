# M4.6 Network (OSC send) cue and the OSC output override (CT-30, PB-10, NFR-07)

Decided 2026-10-27 by the implementer. QLab 5's pages on Network cues and overrides were not read in this session (no web access), so QLab behaviour below is from memory and marked **unconfirmed**; none of it needs the user before merge, but the items marked "ask" are worth a look in the QLab checks.

| Point | openLab | QLab 5 | Decision | Status |
|---|---|---|---|---|
| Cue duration | none: sends when its action starts, completes at once; pre-wait, post-wait and continue modes apply as for a Memo | a Network cue is instantaneous | keep | unconfirmed (matches the brief) |
| What "sent" means | the cue completes when the message is handed to the destination's sender; delivery failure is a `network_send_failed` warning and a show-log line, never the cue's state | the cue does not report delivery | keep | unconfirmed |
| Off the control thread | one worker thread per destination with a 32-message queue; look-ups on short-lived threads | n/a | decided here (the loop must never wait on a socket or a resolver) | decided |
| Message order | per destination, in the order the cues fired | n/a | keep | decided |
| Timing | not sample accurate: sent when the action enters the lookahead window (up to one device block early) or at once if late | n/a | keep; OSC cannot be sample accurate anyway | decided |
| TCP framing | OSC 1.1 SLIP, one connection per message | QLab 5's TCP patches: our reading is SLIP (it is what its own TCP listener speaks, measured in M4.5b) | keep; length-prefixed OSC 1.0 not offered | unconfirmed, **ask** whether a QLab TCP *send* patch can be set to either framing |
| Override scope | engine-wide, every open workspace, in memory only; off after a restart | Overrides are an app-level window, not saved in the workspace | keep | unconfirmed |
| Override effect | Network cues run, complete, auto-follow; send nothing; logged at info | disabled output still lets cues run | keep | unconfirmed |
| Override state to clients | `network_output_disabled` in `status` (sent early on change) and the `set_output_overrides` request | n/a | keep; M5 shows a clear indicator (PB-10 stays unticked until then) | decided |
| Reachability before GO (NFR-07) | broken before GO for: missing network patch, empty/malformed host, port 0, malformed or oversized OSC message. A host **name** that does not resolve is **not** a problem: GO sends, the worker resolves the name and a failure is a `network_send_failed` warning | QLab 5 (manual pp. 371-372) breaks a Network cue for No Patch, Incomplete network patch, Missing message and Invalid OSC message, and never for an unreachable destination | match QLab (user decision 2026-10-30; was stricter, with `network_host_unresolved`, removed). Host/port checks stand as the reading of "incomplete network patch" (assumed row in open-qlab-questions) | decided |
| Probing | **none**: no ping, no connect, no periodic check of a destination. Only name resolution (to fill the address cache), on open, on patch change and every 10 s of sample time for a name that failed | QLab does not probe | UDP cannot tell if anyone listens; a TCP connect-check would open connections to the show's devices unasked | decided |
| Failed look-up | a name that fails to resolve is logged once per run of failures and retried every 10 s; the cue is not broken and a send to it resolves the name itself on its worker (never the control thread) | n/a | the look-up only fills the sender's address cache | decided |
| Message limits | address starts with `/`, printable ASCII, no spaces, at most 512 bytes; at most 32 args; strings at most 4096 bytes, no NUL; finite floats; encoded message at most 8192 bytes | QLab accepts more | conservative caps so one message is one datagram on every platform (macOS default limit 9216); invalid is a cue problem, never a panic | decided |
| `* ? [ ] { }` in the address | allowed, sent as written | QLab sends the address as typed | keep | unconfirmed |
| Hosts | IPv4, IPv6 (brackets allowed) or a host name; digits-and-dots that are not an IPv4 address are rejected as a typo | n/a | keep | decided |
| Address choice | UDP (and TCP, in order) prefers IPv4 addresses when a name resolves to both; the addresses the look-up found are reused for every send (no resolver call per message) | unverified (on macOS `localhost` can resolve to `::1` first, and a receiver bound to IPv4 would never see the datagram) | keep | decided, QLab unverified |
| Late messages | a message that waited more than 1 s in its destination's queue is dropped and warned as "destination too late" | n/a | a cue fired seconds late on stage is worse than none | decided |
| Override and queued messages | turning the override on also stops messages already queued (the sender checks it before each send); only a message already being sent goes out | n/a | keep | decided |
| Sender limit | 64 senders; an idle one (empty queue) is dropped to make room | n/a | keep | decided |
| Look-up threads | at most 8 alive (timed-out and forgotten ones count until they answer), one per host and port; if hung ones fill every slot one log line says so | n/a | keep | decided |
| Address refresh | a name that resolved is looked up again every 60 s of sample time (same slots/limits as retries); a failed TCP send clears the destination's cached addresses and looks up at once; a refresh that fails keeps the last-known addresses (one log line per failure streak); each sender has its own address snapshot | n/a | a host that changes address (DHCP, console reboot) must be followed, and a DNS blip must not break a working show | decided |
| Retry clock | retries and the 20 s look-up timeout run on sample time, which stands still during an audio outage; a failed name is retried once audio is back | n/a | keep (documented) | decided |
| UDP source port | one socket per address family, so a receiver sees one stable source port | n/a | keep | decided |

## Not in this task

- Editing a Network cue's destination, address and arguments needs `CueProperty` commands (none exist for the Network fields); progress archive M4.6a.
- The indicator and the Overrides UI (PB-10 "clear on-screen indication"), the Network cue inspector and the network patch editor: progress archive M5.
- `EngineWarning::Unsupported` (and its wire form) is no longer produced by any cue kind; removed in M4.6c; a client still decodes a legacy `unsupported` warning as an unknown kind (`warning.unknown`).
- The show file is unchanged: no `format_version` bump.
