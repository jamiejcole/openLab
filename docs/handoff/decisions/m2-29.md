# M2.29 decisions (media follow, background detection, auto relink)

Design: stat polling on a watch thread plus `fsgetpath(2)` by (device, inode) to follow a moved file. macOS bookmarks were rejected (opaque per-OS blobs in a cross-platform JSON file, bigger CoreFoundation FFI, resolving can mount a volume or block). Also rejected: FSEvents/notify, a kqueue per file, a folder scan, following as an undo step, lazy remap in History, hints in the cue model, auto-relink by unique name.

Points QLab did not settle for us, decided by the orchestrator (user-delegated authority, 2026-10-27; unconfirmed against QLab 5):

- **R2a**: the display name of a cue named after its file includes the file extension, because the cue then shows exactly which file it plays.
- **R5**: keep show-file media hints (M2.29d) so files moved while the show was closed are still found, because shows are routinely reorganised between sessions.
- **R6**: path first: a new file at the old path wins over the renamed one, because the stored path is what the operator last saw play and following must never swap in a different file.
