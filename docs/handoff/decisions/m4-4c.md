# M4.4c decisions (default patch mapping)

Orchestrator decisions (2026-10-27; QLab 5 maps a new workspace's audio patch to the current output device automatically; the details below are unconfirmed against QLab):

- **Per patch**: any patch with no mapping entry in this machine's `settings.json` gets its N outputs mapped to the playable device's outputs 1..N, whenever a device is playable (new workspace, show from another Mac, a patch added later by AddPatch). An existing entry is never overwritten. Because no "clear mapping" command exists yet, M4.4g must store a cleared mapping explicitly (empty / `none` entry) so the default does not re-apply.
- The mapping is written to the machine settings (keyed by workspace id) off the control thread; an `info` show-log line says `mapped patch 'Main Outputs' to <device> outputs 1–2`.
- **Too-small device**: no partial mapping (it would silence and break cues and block later self-healing). The patch stays `Unmapped` with one `warn` log (`device X has M outputs, patch 'P' needs N`) per patch and device; a different or bigger device is tried again at the next sync.
- No playable device (none, or an outage): nothing is mapped; the next sync with a device maps. Offline backend: the first configured device.
- No protocol change.
