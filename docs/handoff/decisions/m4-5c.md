# M4.5c decisions (OSC passcode rights table)

QLab 5 was measured for name, notes and pre-wait writes only (OSC findings, M4.5b). The rest below is the implementer's reading of QLab's documented rights table (View reads and edits notes; Edit changes cue properties and selects; Control runs transport and moves the playhead), unconfirmed against QLab.

| Point | Decision |
|---|---|
| View | Every read; writing `notes`; `/updates`; `/udpReplyPort`. |
| Edit | Writing `name`, `number`, `preWait`, `postWait`, `armed`, `flagged`; `/select/...`. Armed and flagged are cue edits, not transport. |
| Control | `/go`, `/stop`, `/hardStop`, `/panic`, `/pause`, `/resume`, `/playhead/...`, all cue verbs (start, stop, hardStop, panic, pause, resume, load, reset, preview), cue OSC triggers. An address nothing answers to needs Control too, so a peer without it cannot probe which triggers exist. A trigger shaped like a read (`/cue/zz*/name`) is found after the read check, so firing any trigger is checked for Control again once found. |
| `/updates` | Any access level, as QLab's docs say: no right needed and no reply. The updates carry cue data, so they are sent only to subscribers with View, judged when sent. |
| Edit/Control without View | Cleared on load (warning). `allows()` also ignores them, so a broken table never grants more than it says. |
| `/connect` no argument | Replies `ok:` + the No Passcode rights; stores nothing (no table slot, no failure counted, not a known address). Other types or extra arguments are a wrong passcode when the table has rows. With no rows any argument is accepted (a migrated open show). |
| Connected peer | Keeps its rights against a later no-argument or wrong `/connect`; a right passcode replaces them. |
| Table edits | Sessions end if a row was removed or changed, or No Passcode changed; adding a row keeps them. |
| Passcodes | Commands: 1 to 32 ASCII digits (QLab's are numeric, unconfirmed), at most 16 rows. Load keeps a non-digit passcode (a migrated v3 text) with a warning rather than lock the show out. |
| Default | New workspace: No Passcode none, one random 4-digit passcode with all rights. Core takes the seed (`OscAccess::new_workspace(seed)`); the engine draws it from the OS. |
| Reply budgets | The strict budget and small frame limit apply to a peer without View. The budget exemption is only for a UDP peer connected by a passcode while strangers have no View. |
| M4.15h | Done: each doc's table is its mirror's `access()`, and `Osc` keeps one `Sessions` (connects, subscriptions, lockouts, known addresses) per doc; the reply byte budgets are one table per IP (`Budgets`). |
| Connected peer's guesses | Count toward the per-IP and global lockouts like anyone's; while locked out its `/connect` is `denied` (it keeps its session and rights). Without this a view-only peer could search the table for a Control row without limit. |
| Random source | If the OS random source fails the default passcode comes from the clock and a warning is logged. |
| Known addresses (M4.5d) | The exemption only passes the global budget, never the address's own lockout; wrong guesses during a lockout still count. |
| Rightless sessions | At most 64 sessions without rights (bare `/updates` or `/udpReplyPort`) while strangers have no View; the silent-longest is evicted; sessions with rights never are. |
| Success and the failure count | A correct `/connect` does not clear the IP's failures (4 wrong + 1 right in a loop would never lock out); they age out. |
| Numeric passcodes | An int/long argument never matches (leading zeros are ambiguous; QLab sends a string). The generated default is 1000 to 9999. |
| Trigger probe | A peer without Control that sends a trigger-shaped read gets the same `error` as for a missing cue (no disclosure; not `denied`, which would also hide real missing-cue errors from View peers). |
| Table edits and known addresses | A table edit ends sessions but keeps the known addresses; a different workspace forgets them. |
