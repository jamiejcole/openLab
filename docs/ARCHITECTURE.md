# openLab Architecture

Status: agreed for v0.0.1. Changes to anything in this document need orchestrator sign-off and an update here in the same commit.

Requirement IDs (e.g. `NFR-01`) refer to [`REQUIREMENTS.md`](../REQUIREMENTS.md).

---

## 1. Overview

openLab is two programs that talk over a local socket:

```
┌──────────────────────── openlab-engine (Rust, headless) ────────────────────────┐
│                                                                                  │
│  audio thread (cpal callback)  ◄── lock-free SPSC queues ──  control thread      │
│   mixer, voices, fades,            (time-stamped commands)    owns Engine + N    │
│   matrix, patches, meters    ──►  (status / returns)          Docs (Workspace,   │
│        ▲                                                       CueEngine, undo)  │
│        │ SPSC ring buffers of decoded audio                         ▲            │
│  disk threads (decode → resample → buffer)                          │ channel    │
│                                                                     │            │
│  network threads (tokio): WebSocket server (UI protocol), OSC UDP/TCP 53000      │
└──────────────────────────────────────────┬───────────────────────────────────────┘
                                           │ WebSocket, JSON, 127.0.0.1, token auth
                     ┌─────────────────────┴───────────────────┐
                     │ openLab.app — Swift + AppKit (macOS)     │   Windows UI: later (TBD)
                     │ thin client: renders state, sends cmds   │   Web remote: later (NET-03)
                     └─────────────────────────────────────────┘
```

- **The engine is the single source of truth.** It owns the workspace model, undo history, cue runtime state, timing and audio. UIs mirror state and send commands; they never compute show behaviour.
- **One engine process holds every open workspace** (at most 8, REQUIREMENTS §21): one audio device, clock and mixer shared by N `Doc`s, each with its own workspace, undo history, cue engine and runtime state (QLab 5 runs several workspaces in one app; one process can bind OSC 53000 and answers for all of them).
- **UI faults cannot stop playback** (NFR-01): the UI is a separate process. If it dies the engine keeps playing and relaunches it.
- **Platform-specific code is thin.** The engine is portable Rust (macOS + Windows CI from day one). Only the UI is per-platform.

## 3. Engine internals

### 3.1 Threads

| Thread | Owns | May block? | Talks via |
|---|---|---|---|
| **Audio** (cpal callback, OS real-time priority) | `Mixer`, voice pool, fade ramps, output patches | **Never** | `rtrb` SPSC queues in/out; atomics for meters, clock |
| **Control** (one thread, event loop) | the shared `Engine` (mixer controller, voice and patch-slot allocators, device state) and N `Doc`s, each with `Workspace`, `CueEngine`, undo stack, scheduler | Briefly (no disk I/O on it either — hand to I/O helpers) | `crossbeam-channel` inbox; SPSC to audio; broadcast to network |
| **Disk** (small pool, default 2) | decoders, resamplers | Yes (reads) | per-voice SPSC ring buffers to audio; request channel from control |
| **Disk open** (pool, default 4) | opening stream files, so a hung open never holds a disk worker; opens of one volume (the probe gate's volumes) hold at most all openers but one, so a dead share never blocks opens elsewhere; an open on a volume with nothing in flight that finds every opener held (dead shares on several volumes) gets an extra opener at once, at most 16 extras; an extra only takes opens on volumes with nothing in flight and exits when there are none, so the bound is reached only with opens hung on 18 or more volumes at once; past it such an open waits for an opener to come free | Yes | job queue from the disk streamer; the opened decoder back to the stream's disk worker |
| **Network** (tokio runtime, 1–2 threads) | WebSocket sessions, OSC sockets | Async | forwards parsed commands to control inbox; receives broadcasts |
| **Writer** (logging + saving) | log file, atomic saves | Yes | channel from control (and a lock-free queue from audio for RT events) |
| **Watch** (`openlab-watch`, M2.25) | the media files' stat state (metadata only, no decoding) | Yes (a hung network volume can block a stat) | job channel from control (watch, unwatch, reset); one batched `Inbox::Watch` per pass, only when something changed; a control-side watchdog abandons a stalled worker |
| **Net send** (one per Network-cue destination) and **net look-up** (short-lived, at most 8) (M4.6) | the destination's socket use; a host-name look-up | Yes (connect, send and name resolution can block) | bounded queue from control per destination; answers (`SendFailed`, look-up result) through the control inbox |

The watch thread (`openlab-watch`) polls every cataloged media file's metadata for missing, back, changed and moved files (details: [`docs/persistence.md`](persistence.md) "Media watch and follow", [`docs/control.md`](control.md) "Media watch"). Media probes and preloads (which decode whole files) run on a small probe-worker pool (2) that answers through the control inbox, never on the control thread. Opening and closing the output device (which can block in the host's audio system) run on a device thread that owns the stream, and listing on a device-list thread; both answer through the control inbox as well. Reading a show (open, recovery check and scan) runs on a document worker that answers through the inbox too, and saves and autosaves go to the writer thread; the control thread only clones the workspace and polls for the result. The worker also builds everything an opened doc needs (workspace, cue engine with its problem cache, media catalog index, plan checks) as `DocParts`, so installing a doc on the control thread is an insert plus probe jobs and slot commands, within one audio block (~5 ms) even for 2,000 cues; a closed doc is dropped off the control thread (writer/doc thread). One doc read runs at a time engine-wide (a second is `command_refused`). The control loop ticks every doc and wakes at the earliest `wait_hint` of any. The control loop itself (wake rules, voice ids, feedback, reconciliation of lost mixer events) is in [`docs/control.md`](control.md).

### 3.2 Clock and scheduling (NFR-20/21/22)

- The **audio device's sample counter is the master clock**. The audio thread publishes `samples_rendered` (AtomicU64) after each callback.
- All show timing (pre-wait, post-wait, waits, fades, loop points) is expressed at runtime in **sample time** at the device rate. The show file stores seconds (f64); conversion happens when scheduling.
- The control thread never "sleeps until" a cue time. It computes target sample times and sends **time-stamped commands** (`StartVoice { at: SampleTime, .. }`) to the audio thread, which applies them at the exact sample within the block. This is what makes simultaneous starts sample-accurate.
- GO handling: control receives GO → `start = now_sample + one block` → sends commands. Latency = queue hop + ≤1 block.
- The control loop wakes on (a) inbox message, (b) the next scheduled deadline, or (c) a 5 ms tick, whichever comes first, to advance state transitions (pre-wait → running, auto-continue, etc.). State transitions are computed from sample time, so wake jitter never shifts audio.
- The cue engine carries out deadlines before `now + lookahead` (lookahead = one block, end excluded), so a deadline inside the next block is committed on its exact sample despite wake jitter; a deadline already passed starts at `now` without shifting later cues. Details: `docs/cue-engine.md`.

### 3.3 The core is pure (NFR-41, QA-02)

`openlab-core` contains the behaviour and no side effects:

```rust
// shape, not final API
impl CueEngine {
    fn handle(&mut self, ws: &Workspace, input: Input, now: SampleTime) -> Vec<Action>;
}
// Input:  Go, Stop(cue), Panic, Tick, VoiceFinished(id), LoopReached(id), ...
// Action: StartVoice{..}, StopVoice{..}, Ramp{..}, SendOsc{..}, StateChanged{..}, Log{..}
```

The engine binary executes `Action`s. States, transition table, timing and GO/playhead rules: `docs/cue-engine.md`. Tests drive `CueEngine` with a virtual clock: no threads, no sleeps, fully deterministic. Property tests (`proptest`) generate random workspaces and input sequences and check invariants (no cue in two states, every started cue eventually stops or loops, playhead always valid, undo∘redo = identity, etc.).

### 3.4 Real-time rules (NFR-02) — enforced, not hoped for

On the audio thread:
- No allocation or deallocation. All voices, buffers and ramp slots are preallocated at engine start (pool sizes from settings; default 128 concurrent cue voices). Objects that must be freed are sent back to the control thread on a return queue.
- No locks, no syscalls, no logging, no formatting, no disk access. RT events (xrun, voice ended, loop point) are pushed as small `Copy` structs onto an SPSC queue. One exception: the device callback reads the monotonic clock (`Instant::now`) twice per block to measure the engine load (M4.7a, DX-03); it neither allocates nor locks and is normally served without a kernel entry (macOS commpage, Windows `QueryPerformanceCounter` from the TSC, Linux vDSO; QPC falls back to a kernel-mediated timer on hardware without an invariant TSC and on some VMs). The timing runs inside the callback's `assert_no_alloc` guard and its `catch_unwind`. Results leave through atomics only.
- `assert_no_alloc` wraps the callback in debug and test builds; any allocation fails the test suite.
- The callback body runs inside `catch_unwind`. On a panic it outputs silence for that block, sets an engine-fault flag, and the control thread reports it loudly. The mixer notes the unit it is working on (a voice, a command, a patch matrix, a device output, the master, the meters; a plain field write) and confines the fault to it, so a fault that repeats every block or every other one cannot silence the rest of the show: a voice blamed in 3 blocks within 16 (`FAULT_LIMIT`, `FAULT_WINDOW`), or one whose command panicked, is dropped (`VoiceFinished { Faulted }`; its cue breaks with `stream_failed` and an `audio_fault` notice); a patch is reset to silence, an output or the master to unity (the only value the engine gives them), and reported (`Event::StageFaulted`), the control thread sends its settings again from its own copy, and at the same limit the unit is disabled (a patch's cues break and the patch moves to another slot; an output stays silent, the master is bypassed at unity, the meters stop; each is a warning in force; disabled units are also published as atomics, so a lost report is found). Faults no unit is blamed for rebuild every patch (silence), output and the master (unity) at the limit, and the control thread sends them all again (docs/audio.md "Faults", docs/control.md "Mixer faults"). (Panics must not cross the FFI boundary into the OS audio thread.)

### 3.5 Audio pipeline

```
file ─► disk thread: symphonia decode ─► rubato resample to device rate ─► ring buffer (≈2 s)
                                                                              │
audio thread: voice reads ring ─► trims/loops/slices ─► cue fades (in/out) ─► channel levels
           ─► routing matrix (file ch → cue outputs → patch outputs) ─► Fade-cue ramps
           ─► output patch (level, mute, delay, polarity) ─► master ─► device ─► meters (atomics)
```

- **Shared mixer, several workspaces** (M4.15): the mixer sees voices and patch matrices, not docs. Patch matrix slots (the shared 64) come from a free-list allocator keyed `(DocId, PatchId)`, so removing or reordering a patch never reroutes a running voice; a freed slot is zeroed, and with no slot free the patch is `Unmapped` with a `mixer_patches_exhausted` warning. A workspace's master level is folded into its matrix gains (workspace master x patch master x output level) and the mixer master stays at unity. `VoiceId`s come from one engine-wide counter with an `owner: VoiceId -> DocId` map; mixer events, stream errors and meter listings are routed by owner, and an event for an unowned voice (a closed doc's) is ignored. Device-output delay (to be removed to match QLab 5, #404) is one value per physical output, so `sync_delays` runs over every doc's mapped patches and a conflict is an `output_delay_conflict` warning in each doc whose patches use that output. Device loss stops every doc.
- **Loaded** state = ring buffer primed. The engine keeps cues near the playhead primed (next 16 cues by default, plus targets of those cues and any cue with a hotkey/OSC trigger; at most 64 primed streams for the whole engine and never more than half the disk streamer's open-stream limit, shared between the open docs by demand (each gets what it wants while the wants fit; past that, max-min fair shares), so primes never take the permit a start needs and an idle workspace takes none from a busy one). Primed cues meet NFR-20; a cold cue starts as soon as its buffer fills (~tens of ms) and this is shown as a warning, never a failure.
- Optional per-cue **preload to RAM** (AUD-05) decodes the whole file once, within one memory budget for every open workspace together.
- **Fades** are per-voice gain ramps evaluated per sample on the audio thread from a curve id + start/end gain + start/end sample (no per-sample allocation, no table rebuilds). Curves: linear, equal-power, S-curve, log, exp.
- **Loops/slices/devamp** are resolved on the audio thread from a preloaded slice table; the disk thread is told to seek ahead of loop points so the ring never starves.
- **Meters**: per output channel peak written to atomics; the control thread samples them at ≤30 Hz for clients.
- **Device loss** (NFR-08): cpal error callback (or the device gone from the list) → control thread marks the device offline and attempts reopen on a backoff; every cue playing on the device stops at once (hard stop; QLab 5 behaviour, M4.2g) and shows "broken" (`device_lost`) until the device is back, then idle; no automatic resume, whatever the outage length (sample time stands still while no stream runs; every pre-wait, post-wait and auto-continue/auto-follow pending at the loss is cancelled, for all cue kinds, so nothing scheduled before the outage fires after it; only the operator's GO restarts the show); cues routed to it are broken meanwhile; nothing panics. Policy: `docs/control.md`, Devices.

### 3.6 Offline render driver (QA-03, QA-05, NFR-23 proxy)

`openlab-audio` exposes a driver that calls the exact same mixer callback in a loop, writing into memory instead of a device. It drives the engine faster than real time with no hardware. Used for:
- sample-level assertions (a fade at 50% is at the expected gain on the expected sample; two cues start on the same sample);
- accelerated soak tests (24 h simulated) checking memory, drift and invariants;
- CPU budget tests: **64 streaming stereo voices with active fades must render at ≥ 10× real time on one core of the Intel CI runner** (2× headroom over the 32-voice NFR-23 target on hardware closer to a 2014 Mac mini).

## 4. Model and commands

- **Workspace** → `cue_lists: Vec<CueList>`, `patches: Vec<OutputPatch>`, `settings`. **CueList** → ordered top-level cues; **Group** cues contain child cues (tree).
- **Cue**: `id: Uuid` (stable, internal), `number: Option<String>` (free text, unique when set), `name`, `notes`, `color`, `flagged`, `armed`, `pre_wait`, `post_wait`, `continue_mode`, `triggers`, `second_trigger` (what a trigger does while the cue is active), `second_trigger_on_release`, and `kind: CueKind` (enum: Audio, Fade, Group, Start, Stop, Pause, Load, Reset, Devamp, GoTo, Arm, Disarm, Wait, Memo, Network, …). Targets reference cue `id`, never number.
- **Levels** are dB (f64). Values ≤ −120 dB mean silence (−∞); the file writes −120 for silence.
- **Every mutation is a `Command`** (serialisable). Applying a command returns its inverse. Undo/redo stacks live in the engine (ED-07). Multi-step edits (batch edit, paste, renumber) are grouped into one transaction = one undo step.
- The same command stream is what the UI sends, what OSC edits produce, and later what primary/backup mirroring (RED-01) replays.

## 5. Show file (NFR-40, NFR-04/05/06)

- A workspace is a single JSON file, extension **`.openlab`**, pretty-printed, stable key order, `"format_version": N` at the top. Spec in `docs/file-format.md`.
- Media paths: relative (forward slashes) when under the show file's folder, absolute otherwise. Portable across macOS/Windows (NFR-32).
- **Media identity is path first** (M2.29): a cue's media is its stored path; a file moved or renamed while the show is open is reported missing (broken cue) until relinked. Following moved files is not built (v0.0.2, #145/#146; `docs/persistence.md`). The cue's display name follows its file when `name` is empty (`display_name`, M2.29c).
- **Load**: parse → migrate (`vN → vN+1` chain, each step a pure function with fixture tests) → validate (unique ids, valid targets, sane ranges). Invalid content produces load warnings or a clean refusal with a reason — never a panic. Fuzzed (QA-04).
- **Save** is atomic: write `name.openlab.tmp` in the same directory, `fsync`, rename over the original.
- **Autosave/recovery**: every N seconds (default 30) when dirty, to `<app-support>/openLab/Recovery/<workspace-id>-<path-hash>.openlab` (bound to the show file's path, so a duplicated show is never offered the original's work; `<workspace-id>.openlab` before the first save). On launch, a recovery file newer than the show file triggers a restore prompt. A recovery file is never deleted on a timestamp comparison: older ones are moved aside and deleted only after a successful save.
- **Backups**: on each manual save, the previous version is kept in `<app-support>/openLab/Backups/<workspace-id>-<path-hash>/` (rolling, default 20; per show path so duplicates do not rotate each other out).
- Details of the I/O (file names, rotation, recovery decision, settings schema, relink flow): `docs/persistence.md`. Pure logic is in `openlab-core`; file work is in `crates/engine/src/persist/`. Saves clone the workspace and run on a writer thread, never the control thread.
- **Per-machine settings** (device mapping for each workspace's patches, engine preferences) live in `<app-support>/openLab/settings.json`, not in the show file (WS-06/07). UI-owned state (window layout, recent files) lives in the macOS app's UserDefaults, not there (decision M1.14: [handoff/decisions/qlab-confirm.md](handoff/decisions/qlab-confirm.md)). `<app-support>` = `~/Library/Application Support` (macOS), `%APPDATA%` (Windows).

## 6. UI protocol (engine ↔ UI)

- **Transport**: WebSocket on `127.0.0.1`, random port. JSON text frames; meters may move to binary frames if profiling demands it.
- **Auth**: the engine generates a random token at start and writes `{port, token, pid}` to `<app-support>/openLab/engine.json` (mode 0600). Clients send it in `hello`.
- **Versioning**: `hello { protocol_version }`; the engine refuses incompatible clients with a clear error.
- **One connection, one workspace** (M4.15): `hello` may name a doc (`workspace`); the connection is then bound to it, `welcome` carries that doc's snapshot, and every command, transport and request acts on it, with revisions and `runtime_seq` counted per doc. A `hello` without one is an unbound app connection: `welcome` lists the open workspaces (`doc`, `workspace_id`, name, path, dirty, `path_hash`: the hash naming its autosave), and a `workspaces` message follows each change to the list, a name, a path or a dirty flag. Workspace-bound messages on it answer `no_workspace`. `new`, `open`, `open_recovery` answer `opened { doc }` (an already-open path answers `already_open`); `close` (bound, or `close { doc }`) refuses with `unsaved_changes` unless `discard_changes`, then sends `closed { doc }` to its connections and closes them. `revert` does not exist (QLab 5 has none). Broadcasts are tagged with their doc and each connection gets only its own doc's (plus `workspaces` when unbound); the OSC task sees all. Two actions are app-scope, sent on any connection and applied to every doc: `panic` (Esc, once or twice) and hotkey triggers (a hotkey fires in every open workspace, in front or not); Pause All, GO and the other transport keys act on one doc, the front window's, which is the UI's notion (no engine front workspace). Opening a file whose workspace id is already open gives the new doc a fresh workspace id and marks it dirty (QLab 5 does the same for a Finder duplicate).
- **Messages** (envelope `{"type": "...", ...}`):
  - client → engine: `hello`, `command` (model edit, with client request `id`), `transport` (go, stop, panic, pause_all, resume_all, playhead, start/stop/pause cue), `undo`, `redo`, `request` (open, save, save_as, new, relink, device list, …), `goodbye`.
  - engine → client: `welcome` (full snapshot), `model_changed` (entity upserts/deletes + monotonically increasing `revision`), `runtime` (cue state changes, event-driven), `progress` (elapsed/remaining for running cues, ≤ 30 Hz batch), `meters` (≤ 30 Hz), `log`, `warnings`, `result { id, ok | error }`.
  - A client that sees a `revision` gap requests a fresh snapshot.
- **Contract tests**: Rust protocol types (in `openlab-core`) are the source of truth. A Rust test writes one golden JSON fixture per message variant to `engine/fixtures/protocol/`; Swift tests decode every fixture and re-encode client messages for Rust to decode. CI fails on drift. Spec in `docs/protocol.md`.

## 7. OSC (NET-01/02/05, CT-30)

- UDP and TCP (SLIP-framed) on port **53000**; UDP replies to the sender on 53001 — matching QLab so existing tools connect unchanged.
- Address space follows QLab 5's OSC dictionary for the v0.0.1 subset (see REQUIREMENTS §21): `/go`, `/stop`, `/panic`, `/pause`, `/resume`, `/playhead/{number}`, `/select/{number}`, `/cue/{number}/start|stop|pause|...`, `/cue_id/{id}/...`, `/workspace/{id}/...` prefixed forms, `/connect {passcode}`, `/updates {1|0}`, JSON replies where QLab sends them. `docs/osc.md` lists exactly what is implemented, written in our own words.
- **Several workspaces** (M4.15; QLab 5 sends a message to every open workspace listening on its port): one listener serves all docs. A message with no workspace prefix goes to every doc listening on that port, whichever window is in front, so an un-prefixed `/go` fires every open workspace's GO; `/workspace/{id}/...` and `/workspace/{name}/...` pick one. A query gets one reply per doc, each with its `workspace_id` and the address rewritten to the prefixed form; a doc where it fails replies with an error status. `/connect` and its passcode, session and lockout state are per doc (keyed peer + doc): un-prefixed, every doc checks its own passcode and answers (`ok:<rights>` or `badpass`); closing a doc ends its sessions; per-IP budgets stay per IP. `/updates` goes to every doc but gets no reply, and a doc sends updates only to sessions connected to it; a prefixed `/updates` is an error. `/version` and `/workspaces` are application messages; `/workspaces` is one reply listing every open doc in open order (not front order), without `workspace_id`. With no doc open an addressed message errors like an unknown workspace id. Per-workspace listen ports are a later setting (#151); the engine never needs a "front" workspace for OSC.
- Incoming OSC is parsed on network threads and becomes the same `transport`/`command` inputs the UI sends. Malformed packets are dropped and counted.
- Network cues send OSC from a worker thread per destination, never from the audio or control thread (`docs/control.md`, Network output). The OSC output override (PB-10) is an in-memory engine flag, checked when the cue sends and reported in `status`; it is not stored in any file.

## 8. Process lifecycle & supervision

- `openLab.app` contains the engine at `Contents/MacOS/openlab-engine`.
- **App launch**: read `engine.json`; if a live engine answers, connect (UI was restarted). Otherwise spawn the engine (detached, its own process group) and connect. The engine starts with no workspace open; the app decides what to open (recovery check, last workspaces, none) by sending `new`/`open`/`open_recovery`.
- **UI quits normally**: if cues are running, confirm (SM-05); then send `goodbye { shutdown: true }` and the engine exits after a final recovery write for every dirty doc.
- **UI crashes** (socket drops without `goodbye`): engine keeps playing, logs it, and relaunches the app after 1 s via the OS (`open -b <bundle id>` on macOS, which brings it to the front so keyboard GO reaches it), at most 3 times per minute. An app whose process still runs (the pid it gave in `hello`, with the same process name) is not relaunched: the engine waits for it to reconnect and relaunches it only once that process is gone. The relaunched UI reconnects and receives a full snapshot.
- **Engine crashes** (must not happen; tested heavily): UI shows an alarm that cannot be missed (a floating, non-modal, always-on-top panel with a sound and a critical Dock bounce; it never takes keyboard focus, so transport keys keep working in windows still bound to a live engine), relaunches the engine and offers to restore from the recovery file. Audio has stopped — this is the one unrecoverable case, which is why the engine is kept small and isolated from GUI frameworks. Holding all workspaces in one process (M4.15) widens this: a crash stops every open show, not one. Accepted to share one device, clock and OSC port as QLab does; mitigations are the no-panic rules, fuzzing, the soak runs and a recovery file per dirty doc.
- Show Mode sleep prevention (SM-07) is asserted by the engine (IOPMAssertion on macOS) so it holds even while the UI restarts.

## 9. macOS app (Swift + AppKit)

- **Swift 6, AppKit only, deployment target macOS 12.0.** No SwiftUI (immature tables/outlines on 12), no Observation framework (macOS 14+). Use Combine and delegates. The compiler's availability checking against 12.0 is the guard for Monterey.
- **UI built in code** — no storyboards or XIBs (main menu included). Keeps diffs reviewable and avoids XML merge conflicts.
- **No third-party Swift dependencies** without orchestrator approval. `URLSessionWebSocketTask` for the socket, `Codable` for messages.
- **Structure**: `EngineClient` (socket, reconnect, message codec) → `WorkspaceStore` (mirrored model + runtime state, publishes changes) → AppKit view controllers. View controllers never talk to the socket directly. One window per open workspace, each with its own `EngineClient` bound to that doc (`hello { workspace }`) and its own `WorkspaceStore`; an app-level session holds the unbound connection and owns launch, New/Open/recovery flows, the workspace list, recent files and the quit walk (one save prompt per dirty workspace). The front window decides which doc GO, Pause All and the other window-scoped keys address; Esc sends the app-scope `panic`. Closing a workspace while cues play asks first; closing the last one shows a launcher window. No `NSDocument` subclass.
- **Main window layout follows QLab 5** (UI-07): toolbar and GO/standby area on top, cue list (`NSOutlineView`, view-based, cell reuse for ≥ 2,000 cues) in the centre, sidebar (cue lists, active cues, warnings), tabbed inspector at the bottom. Dark appearance by default.
- **Assets**: SF Symbols and original artwork only (UI-08). Never copy QLab icons, images, names or text.
- **Strings**: all user-facing text in `Localizable.strings` from day one (UI-06).
- **Project**: generated by XcodeGen from `mac/project.yml`; the `.xcodeproj` is not committed. The engine is built (universal: arm64 + x86_64 via `lipo`) by a build-phase script that calls `cargo`.
- **Not sandboxed** (spawns the engine, opens arbitrary media paths). Hardened runtime + notarisation when an Apple Developer account exists; ad-hoc signed until then.

## 10. Error-handling policy

- Engine Rust code returns `Result`. Workspace lints (`[workspace.lints.clippy]`, all `deny`, `-D warnings` in CI) apply to all three crates: `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `unreachable`, `print_stdout`, `print_stderr`, `undocumented_unsafe_blocks`, `indexing_slicing`. `engine/clippy.toml` relaxes unwrap/expect/panic/print/indexing in tests only; that covers `#[test]` fns and `#[cfg(test)]` items, so integration-test crates and their support modules allow them at the top of the file.
- Nothing in the engine writes to stdout/stderr except through the logging path. The one exception is CLI output in `main` (e.g. `--version`), written via `std::io::Write` with write errors handled (a closed pipe must not panic).
- Failures surface as **broken cue state, warnings, or log entries** — never a crash, never a modal during Show Mode.
- `unsafe` is forbidden in `openlab-core`; allowed elsewhere only with a `// SAFETY:` comment and a test exercising it.
- Every bug fix lands with a regression test.

## 11. Testing strategy & CI

| Layer | Tools | Covers |
|---|---|---|
| Core logic | `cargo test`, `proptest` | state machine, continue modes, groups, control cues, scheduler, commands/undo, migrations |
| Audio | offline render driver | sample-accurate starts, fade curves, matrix/patch math, loops/devamp, RT-safety (`assert_no_alloc`) |
| Engine | integration tests over real WebSocket/OSC sockets on localhost | protocol, OSC subset, save/load/recovery, device-loss simulation |
| Robustness | `cargo-fuzz` (nightly); the OSC-session and protocol fuzz bodies also run on stable in `cargo test` | show file, OSC (one packet; sessions over time), protocol (decoders and the control loop), media decoders |
| Soak / perf | render driver; wall clock for the real-time soak | 24 h accelerated soak (`tests/soak.rs`: generated show, random operator, invariants counted in voices/streams/messages, not RSS); a minutes-long real-time soak of the same show and operator (`tests/soak_rt.rs`, `#[ignore]`, measures real wake jitter on the wall clock; the other permanent wall-clock readers are the ignored perf and CPU-budget gates, and the remaining test files that read it are listed with an issue in `scripts/wall-clock-allowlist.txt`); CPU budget (§3.6) |
| Contract | golden fixtures | Rust ↔ Swift protocol parity |
| macOS UI | XCTest (view logic vs. mock `EngineClient`), XCUITest (against FakeEngine; real-engine UI smoke is a planned CI job, not yet present) | editing flows, show mode, reconnect after engine/UI restart |
| Sanitizers | ASan/TSan (nightly Rust job; Xcode scheme options for Swift) | memory/thread errors |

**CI**: jobs, triggers and runners are described by `.github/workflows/ci.yml` (its comments are the description). Branch protection requires the single `CI Result` job.
- Pin the Xcode version in CI. Xcode 27.1's minimum macOS deployment target is exactly 12.0 — **a future Xcode that drops 12.0 must not be adopted** without a plan for Monterey.

## 13. Windows readiness (NFR-31)

- Engine compiles and passes tests on Windows in CI from the first commit.
- OS-specific code lives in a `platform` module per crate behind `cfg` (paths, sleep prevention, app relaunch, real-time thread priority).
- Paths in the show file are always relative-with-forward-slashes or absolute; compare case-insensitively on Windows.
- The Windows UI technology is decided after macOS v0.x is usable; the protocol is UI-agnostic so this decision does not affect the engine.

## 14. Video (v0.0.2, for orientation only)

The engine will own fullscreen output windows (`winit` + `wgpu`) so video also survives UI crashes. Decoding via FFmpeg (GPL-compatible); a video's audio track feeds the audio engine as a voice so picture and sound share the master clock. Nothing in v0.0.1 may assume the engine is windowless forever.
